# 6.2.1 全局不透明度

全局不透明度描述了绘制在画布上时，颜色的不透明度通道会乘以的值。也就是说，所有的内容在画到画布上之前，其不透明度都会乘以全局不透明度，再画到画布上。设置全局不透明度使用 `globalAlpha` 属性：

```TypeScript
ctx.globalAlpha = 0.8; // 全局不透明度为 0.8
```

如果绘制的颜色本身就是透明的，那么会再乘以全局不透明度。举例来说，如果 `fillStyle` 设为了 `rgba(255,255,255,0.6)`，`globalAlpha` 设为了 `0.8`，那么最后绘制到画布上的颜色就会是 `rgba(255,255,255,0.48)`。

注意 `globalAlpha` 的范围是 `0-1`，也就是说，不能通过将 `globalAlpha` 设置为大于 1 的值来让本身透明的东西变得不那么透明。

# 6.2.2 二维线性变换的数学基础

在 `Canvas2d` 中，我们经常会用到这些行为：缩放、平移、旋转，虽说平移和缩放可以通过调整坐标等参数来实现，但是我们还需要手动计算坐标，而如果是旋转后再缩放、平移，我们就更难手动计算坐标了，因此我们需要一个通用的方式来实现这三个基本操作。在数学上，这三个行为都叫做线性变换，我们可以使用矩阵乘法来描述这一行为，而且借助于矩阵乘法不满足交换律的特性，我们还可以描述出每个行为的执行顺序。

我们可以使用如下三个矩阵来分别描述缩放（Scale）、平移（Translate）、旋转（Rotate）行为：

$\bold{S}=\begin{bmatrix} x & 0 & 0 \\ 0 & y & 0 \\ 0 & 0 & 1 \end{bmatrix}$  $\bold{T}=\begin{bmatrix} 1 & 0 & x \\ 0 & 1 & y \\ 0 & 0 & 1 \end{bmatrix}$  $\bold{R}=\begin{bmatrix} \cos\theta & -\sin\theta & 0 \\ \sin\theta & \cos\theta & 0 \\ 0 & 0 & 1 \end{bmatrix}$

矩阵乘法不满足交换律，即 $\bold{A}\bold{B}\neq\bold{B}\bold{A}$。

三者倒序相乘，即可得出最终的变换矩阵，例如我们需要先旋转，再平移，只需要计算 $\bold{TR}$ 即可。同样，如果要先平移，再旋转，只需要计算 $\bold{RT}$ 即可。

不过实际上，在 `Canvas2d` 中，我们不需要完全理解上述数学内容，只留下一个大概的印象即可，浏览器提供了相当丰富的接口来让你实现这些线性变换操作，而不需要进行复杂的数学计算。

# 6.2.3 在画布中执行线性变换

我们可以使用 `ctx.scale` `ctx.translate` `ctx.rotate` 来实现上述三种矩阵变换操作。例如我们要在坐标 (100,100) 的位置画一个旋转了 30° 的矩形，我们需要先对矩形执行旋转操作，再执行平移操作。变换操作需要倒序执行，因此用代码可以这么写：

```TypeScript
ctx.translate(100, 100); // 平移操作
ctx.rotate(Math.PI / 6); // 旋转使用弧度制
ctx.fillRect(0, 0, 100, 100); // 平移操作已经修改了位置，因此直接在 (0,0) 画
```

而如果先平移再旋转，旋转时沿着左上角的原点旋转，于是平移坐标就不对了：

```TypeScript
ctx.rotate(Math.PI / 6); // 先旋转 30°
ctx.translate(100, 0); // 再横向平移 100 像素
// 这时候的原点就变成了 (50sqrt(3),50)，其中 sqrt 代表平方根
ctx.fillRect(0, 0, 100, 100);
```

这些操作可以随意组合，实现复杂的变换操作：

```TypeScript
ctx.rotate(Math.PI / 4);
ctx.scale(2, 1.5);
ctx.translate(100, 200);
ctx.rotate(Math.PI / 2);
ctx.scale(0.75, 0.8);
```

注意所有的变换都只影响之后绘制的内容，对已有内容没有任何影响。

如果我们自己算出来了矩阵，还可以使用 `ctx.setTransform` 来直接设置变换矩阵：

```TypeScript
function setTransform(a: number, b: number, c: number, d: number, e: number, f: number): void;
```

可以使用变换矩阵描述接口的每个参数：

$$\bold{T}=\begin{bmatrix} a & b & e \\ c & d & f \\ 0 & 0 & 1 \end{bmatrix}$$

一般情况下我们并不会用到这个接口，它的最大用处是重置变换矩阵：

```TypeScript
ctx.setTransform(1, 0, 0, 1, 0, 0); // 重置变换矩阵，此时相当于没有执行任何变换操作
```

# 6.2.4 画布状态机

画布本质上是一个状态机，即它会根据当前的状态形成不同的输出（绘制内容）。例如当 `fillStyle` 为 `red` 时，画出的图形就是红色的，`fillStyle` 为 `yellow` 时，画出的图像就是黄色的。除了颜色，还有很多其他状态，包括字体、描边样式、线参数、变换矩阵等。

现在考虑这些场景：我需要绘制一个 UI，UI 的中间有一个需要旋转 90° 的地方，这时候我们需要在绘制这个地方之前旋转 90°，绘制之后再旋转 -90°；UI 的中间有一部分使用红色绘制，其余地方使用白色绘制，我需要在红色之前将 `fillStyle` 或 `strokeStyle` 设为 `red`，绘制完之后再切换为白色。

我们会发现，如果状态数量少的话，直接设置倒也不复杂，那么加入状态多呢？例如字体、变换矩阵、样式等都需要改变，绘制完之后再改回去，一个个修改就会非常麻烦了。因此浏览器提供了接口来处理这种情况：

```TypeScript
function save(): void;
function restore(): void;
```

其中 `save` 表示保存当前画布的状态，包括样式、字体、变换矩阵等多数设置，注意不包括绘制内容；`restore` 表示回退到上一次保存的状态，如果没有保存状态，那么什么事都不会做。

注意这些状态与操作都只会影响之后将要绘制的内容，而不会影响画布上的已有内容。后面的小节讲的内容也是如此。

示例如下：

```TypeScript
ctx.font = '16px Verdana';
ctx.fillStyle = 'white';
ctx.strokeStyle = 'blue';
ctx.textBaseline = 'top';
// 以上述设置绘制一段文字的填充和描边，白色填充，蓝色描边，16px 字体
ctx.fillText('lhjnb', 0, 0);
ctx.strokeText('lhjnb', 0, 0);

ctx.save(); // 保存当前状态
ctx.fillStyle = 'red';
ctx.strokeStyle = 'white';
ctx.font = '24px Verdana';
// 再以这些设置绘制文字的填充和描边，红色填充，白色描边，24px 字体
ctx.fillText('lhjnb', 0, 100);
ctx.strokeText('lhjnb', 0, 100);

ctx.restore(); // 回退成原来的状态
// 再以原来的设置绘制文字的填充和描边，白色填充，蓝色描边，16px 字体
ctx.fillText('lhjnb', 0, 200);
ctx.strokeText('lhjnb', 0, 200);
```

不同的渐变使用方法基本一致，遵循 `创建渐变->设置颜色->使用渐变` 的流程，不同的地方仅位于创建渐变的步骤。创建渐变时，三者使用不同的方法，我们一个个来讲。

## 创建渐变

对于线性渐变，使用如下方法：

```TypeScript
function createLinearGradient(x0: number, y0: number, x1: number, y1: number): CanvasGradient;
```

其中 `x0` `y0` 描述了渐变的起始点，`x1` `y1` 描述了渐变的终止点。换句话说，`x0` `y0` 描述了渐变开始的位置，在此处渐变程度为 0，`x1` `y1` 描述了渐变结束的位置，在此处渐变程度为 1。使用图解如下：


其中 `x0` `y0` 描述了起始点圆形的位置，`r0` 描述了起始点渐变的半径，`x1` `y1` 描述了终止圆形的位置，`r1` 描述了终止点的半径。使用图解如下：

## 设置颜色

不同渐变设置颜色的方式完全一样，都使用 `addColorStop` 方法：

```TypeScript
function addColorStop(offset: number, color: string): void;
```

其中 `offset` 表示渐变程度，0 表示渐变的起始位置，1 表示渐变的终止位置，`color` 表示这一点对应的颜色。以线性渐变为例，如果我需要做出一个从绿色到黄色再到蓝色的渐变，那么应该这么写：

```TypeScript
const gradient = ctx.createLinearGradient(0, 0, 100, 0); // 从 (0,0) 到 (100,0) 的渐变，即水平向右
gradient.addColorStop(0, 'green');
gradient.addColorStop(0.5, 'yellow');
gradient.addColorStop(1, 'blue');
```

不同的渐变的起始终止位置是不同的，注意区分。

## 使用渐变

最后，我们只需要将渐变赋值给 `fillStyle` 或 `strokeStyle` 即可：

```TypeScript
const gradient = ctx.createLinearGradient(0, 0, 100, 0); // 从 (0,0) 到 (100,0) 的渐变，即水平向右
gradient.addColorStop(0, 'green');
gradient.addColorStop(1, 'yellow');
ctx.fillStyle = gradient;
ctx.fillRect(0, 0, 100, 100); // 会显示出从左到右的渐变，颜色从绿色变为黄色
```

值得注意的是，渐变的坐标是相对于全局的，与图形的位置并没有任何关系。以上面的例子中的渐变为例，渐变从 (0,0) 渐变至 (100,0)，如果你在 (200,0) 的位置画了一个矩形，那么这个矩形会全是黄色，因为它的位置超出了渐变的范围。

不过，你可以通过矩阵变换来修改渐变的位置或旋转缩放等。如果你想再用同样的渐变画整个矩形，那么就可以这么写：

```TypeScript
ctx.fillStyle = gradient;
ctx.translate(200, 0); // 先平移至目标位置
ctx.fillRect(0, 0, 100, 100); // 再在原点绘制矩形
```

渐变也可以传入半透明的颜色，例如从完全透明转为黑色：

```TypeScript
const gradient = ctx.createLinearGradient(0, 0, 100, 0); // 从 (0,0) 到 (100,0) 的渐变，即水平向右
gradient.addColorStop(0, 'rgba(0,0,0,0)');
gradient.addColorStop(1, 'black');
```

使用这种方式，就可以做出类似百叶窗的效果，不过我们目前只会静态的内容，还无法做出动态的效果。

## 注意事项

跨上下文使用渐变似乎是一个未定义行为，例如：

```TypeScript
const gradient = ctx1.createLinearGradient(...); // 使用第一个画布创建渐变
ctx2.fillStyle = gradient; // 然后将渐变赋值给第二个画布
```

此行为在浏览器标准文档中并没有提及，也就是说它是未定义行为，不同浏览器中行为可能不同，有的浏览器可能报错，有的浏览器可能正常运行。因此需要注意避免这种使用方式。

# 6.2.6 滤镜

## 滤镜基本使用

滤镜允许我们使用简单的代码实现比较常见的效果，包括亮度改变、高斯模糊等。它包含这些内容：

- `blur(kernal)`：高斯模糊，`kernal` 指高斯模糊的程度（卷积核大小），越大越模糊，但是值过大的话可能会产生严重的性能问题。
- `brightness(percent)`：调整亮度，`percent` 表示亮度的百分比，`100%` 表示亮度不变，`200%` 可以使亮度变为二倍，`50%` 可以使亮度减为一半。
- `contrast(percent)`：调整对比度，`percent` 表示对比度百分比，`100%` 保持不变，`0%` 将会变为纯黑，`200%` 会提高对比度。
- `grayscale(percent)`：调整灰度值，`percent` 表示灰度百分比，`100%` 变为纯灰度图，`0%` 保持不变。
- `hue-rotate(angle)`：色相旋转，`angle` 表示旋转角度，`0deg` 表示不变，`180deg` 表示色相旋转 180°。
- `invert(percent)`：反色，`percent` 表示反色程度，`0%` 保持不变，`50%` 生成灰色图像，`100%` 完全反色。
- `saturate(percent)`：调整饱和度，`percent` 表示饱和度百分比，`100%` 保持不变，`0%` 生成灰度图，`200%` 生成高饱和度图像。
- `sepia(percent)`：调整为深褐色，`percent` 表示深褐色程度，`0%` 保持不变，`100%` 完全深褐色。可以用于生成老旧照片效果。

这些滤镜可以自由组合，之后赋值给 `ctx.filter`，然后绘制即可生效。注意效果是按顺序施加的，顺序可能对效果有一定的影响。示例如下：

```TypeScript
ctx.filter = 'brightness(120%)contrast(120%)'; // 亮度和对比度调整为 120%
ctx.filter = 'invert(100%)hue-rotate(90deg)blur(4px)'; // 反色 100%，色相旋转 90°，模糊 4px
```

如果不想要滤镜，直接设为 `none` 即可：

```TypeScript
ctx.filter = 'none';
```

注意，直到现在，`Safari` 浏览器依然不支持此特性，也就是说所有的滤镜效果将不会在 `Safari` 浏览器上显示，即 `iOS` 和使用 `Safari` 浏览器的 `Mac` 设备将无法正确显示滤镜。

## 关于 `XML` 滤镜

这一段的内容并不重要，仅做了解，知道有这个功能即可。

最后简单说明一下 `XML` 滤镜，`XML` 滤镜允许你用一段 `XML` 代码实现复杂的滤镜操作，自由度远比字符串更高，但是学习难度也更大，复杂度更高，并不常用。

我们需要先在 `HTML` 中声明一段 `svg` 代码，或是在 `ts` 中写成字符串，然后定义为 `URL`，再使用 `url()` 传递给 `filter` 参数。例如下面是一个复杂的 3D 光源滤镜，我们将它写到 `html` 中：（代码来自 [Filter Effects Module Level 1](https://drafts.fxtf.org/filter-effects/#typedef-filter-value-list)）

```HTML
<filter id="my-filter" filterUnits="userSpaceOnUse" x="0" y="0" width="200" height="120">
    <desc>Produces a 3D lighting effect.</desc>
    <feGaussianBlur in="SourceAlpha" stdDeviation="4" result="blur"/>
    <feOffset in="blur" dx="4" dy="4" result="offsetBlur"/>
    <feSpecularLighting in="blur" surfaceScale="5" specularConstant=".75"specularExponent="20" lighting-color="#bbbbbb"result="specOut">
        <fePointLight x="-5000" y="-10000" z="20000"/>
    </feSpecularLighting>
    <feComposite in="specOut" in2="SourceAlpha" operator="in" result="specOut"/>
    <feComposite in="SourceGraphic" in2="specOut" operator="arithmetic"k1="0" k2="1" k3="1" k4="0" result="litPaint"/>
    <feMerge>
        <feMergeNode in="offsetBlur"/>
        <feMergeNode in="litPaint"/>
    </feMerge>
</filter>
```

然后我们将它赋值给 `filter`：

```TypeScript
ctx.filter = 'url(#my-filter)';
```

这样就可以实现 `XML` 滤镜效果了。此行为只做了解，知道有这个功能即可，完全不需要掌握，需要的时候再去查资料即可。（似乎连现在的大模型都不知道画布的滤镜还能这么用，足以见得这个功能使用场景非常少）

# 6.2.7 混合模式

混合模式描述了将要画到画布上的内容与画布上已有内容混合的方式。混合模式使用 `ctx.globalCompositeOperation` 来设置，例如：

```TypeScript
ctx.globalCompositeOperation = 'source-in'; // 设为 source-in 混合模式
```

浏览器一共提供了 26 种混合模式，具体可以查看[此 MDN 文档](https://developer.mozilla.org/zh-CN/docs/Web/API/CanvasRenderingContext2D/globalCompositeOperation)了解具体的每一种混合模式。下面我们讲一些常用的混合模式。

- `source` 代表将要画到画布上的内容，`destination` 表示画布上的已有内容
- 在 `source-` 和 `destination-` 后面跟着的内容描述了将内容画到哪

## 其他常用混合模式

### `lighter` 混合模式

在造塔群里面我们经常会看到关于黑底动画应该如何绘制的问题，现在我们就可以回答一部分了，答案是使用加算叠加。对于黑色部分，它的 `RGB` 值是 `0,0,0`，与 `destination` 加算后保持不变，还是 `destintaion` 原有的颜色，而对于其他部分，使用加算叠加后，可以直接显示在画面上。因此我们并不需要进行复杂的抠图操作，很可能还扣不干净，这时候我们直接使用 `lighter` 混合模式执行加算叠加，就可以有效果了。假如我们有一个这种素材 `animate`，那么只需要这么写：

```TypeScript
ctx.globalCompositeOperation = 'lighter'; // 加算叠加
ctx.drawImage(animate, 0, 0, 416, 416); // 画到画面上
```

### `multiply` 混合模式

我们有时候还会碰到颜色是黑底+白色的动画图片，这种图片直接使用加算叠加时效果不佳，是因为用法不对。这种图片的本意是让你先使用乘算叠加来上色，再使用加算叠加画到画面上。例如有一个纯白的爆炸素材，我们想要橙色的爆炸，就可以先乘以橙色，这样的话白色部分就会上色为橙色（因为白色的 `RGB` 值归一化后是 `1,1,1`，乘以橙色就等于橙色），而黑色部分保持为黑色，我们就得到了橙色的爆炸图，最后再用加算叠加即可画到画面上。假如我们有一个这种素材 `explosion`，那么可以这么写：

```TypeScript
const ctx = explosionCanvas.getContext('2d'); // 爆炸素材画布
const ctx2 = gameCanvas.getContext('2d'); // 游戏画面的画布
ctx.globalCompositeOperation = 'source-over'; // 先使用默认混合模式
ctx.fillStyle = 'orange'; // 橙色填充
ctx.fillRect(0, 0, 416, 416); // 全部填充为橙色
ctx.globalCompositeOperation = 'multiply'; // 调整为乘算叠加
ctx.drawImage(explosion, 0, 0, 416, 416); // 将素材与背景的橙色乘算，得到橙色的爆炸素材
ctx2.globalCompositeOperation = 'lighter'; // 将游戏画面调整为加算叠加
ctx2.drawImage(explosionCanvas, 0, 0, 416, 416); // 将爆炸素材加算叠加至游戏画面
```

这样，我们就对这种黑底素材提交了一个完美的答卷。

除了这种用法，乘算叠加还可以用来制作蒙版，将需要显示的地方画为白色，不需要显示的地方画为黑色，然后使用乘算叠加，就会只显示白色的部分了。当然还可以与渐变结合，例如人类塔的封面就使用了这种方式（示例为简化版本）：

```TypeScript
const gradient = ctx.createLinearGradient(0, 0, 100, 0); // 创建渐变
gradient.addColorStop(0, 'rgba(255,255,255,1)');
gradient.addColorStop(1, 'rgba(0,0,0,1)');
ctx.globalCompositeOperation = 'multiply'; // 调整为乘算叠加
ctx.fillStyle = gradient;
ctx.fillRect(0, 0, 416, 416); // 与游戏画面乘算叠加
```

# 6.2.8 阴影效果

画布可以用几行代码实现阴影效果，使用如下四个接口：

- `ctx.shadowOffsetX`：阴影横向偏移量，单位像素。
- `ctx.shadowOffsetY`：阴影纵向偏移量，单位像素。
- `ctx.shadowColor`：阴影的颜色。
- `ctx.shadowBlur`：阴影的模糊程度，会给阴影添加高斯模糊，单位像素。

我们只要设置了这四个属性，画到画面上的内容就会有阴影效果。如下例所示：

```TypeScript
ctx.shadowColor = "red"; // 阴影颜色
ctx.shadowOffsetX = 25; // 阴影横向偏移
ctx.shadowOffsetY = 0; // 阴影纵向偏移
ctx.shadowBlur = 10; // 阴影模糊
ctx.fillStyle = "blue"; // 填充颜色
ctx.fillRect(20, 20, 150, 100); // 以蓝色绘制一个矩形，将会有红色阴影效果
```

效果如图：

![](https://feishu.cn/file/Vv5IbT7oZo6awvxXp6QcMS7Knuc)

阴影会受到 `globalAlpha` 的影响以及所画内容不透明度的影响，例如如果 `globalAlpha=0.5`，绘制一个 `rgba(255,255,255,0.5)` 的矩形，那么阴影的不透明度将会是 `阴影颜色的不透明度 * 0.5 * 0.5`。因此，你不能通过绘制一个透明的内容来只获得阴影。

如果你需要只获得阴影，可以考虑与 `globalCompositeOperation` 结合使用，先做一个阴影颜色的画布，再使用 `destination-in` 获取到将要画到画布上的内容区域，这样你就获取到了阴影内容，再将此画布画到最终画布上，并添加高斯模糊的滤镜以及需要的偏移量，就可以仅将阴影画到目标画布上。假如我们需要获取一个图片的阴影，那么可以这么写：

```TypeScript
const ctx1 = shadowCanvas.getContext('2d');
const ctx2 = canvas.getContext('2d');

ctx1.fillStyle = 'red'; // 使用红色阴影
ctx1.fillRect(0, 0, shadowCanvas.width, shadowCanvas.height);
ctx1.globalCompositeOperation = 'destination-in';
ctx1.drawImage(image, 0, 0, image.width, image.height); // 将图片画上去，这样就会只保留图片的红色阴影

ctx2.filter = 'blur(4px)'; // 目标画布添加高斯模糊滤镜
ctx2.drawImage(shadowCanvas, 25, 0); // 将阴影画布偏移 (25,0) 画到目标画布上
```

# 6.2.9 区域裁剪

区域裁剪使用场景较少，但是在部分场景下会有一些意想不到的效果。区域裁剪允许你将之后的绘制内容限定在指定区域内，在区域之外的内容将不会绘制。它使用如下接口，共有四种用法：

```TypeScript
function clip(): void;
function clip(path: Path2D): void;
function clip(fillRule: CanvasFillRule): void;
function clip(path: Path2D, fillRule: CanvasFillRule): void;
```

当传入 `path` 时，会将区域限定在传入的路径中，否则将会限定在画布现有路径中，即从上一次 `beginPath` 到现在所声明的路径。`fillRule` 即为环绕原则，参考上一节课的内容。

下面我们展示一个示例，此示例使用 `clip()` 方法根据圆弧的形状创建一个裁剪区域。然后绘制了两个矩形；只有在裁剪区域内的部分才会被渲染。

```TypeScript
ctx.beginPath();
ctx.arc(100, 75, 50, 0, Math.PI * 2); // 圆形形状
ctx.clip(); // 使用圆形裁剪

ctx.fillStyle = "blue";
ctx.fillRect(0, 0, canvas.width, canvas.height); // 绘制内容
ctx.fillStyle = "orange";
ctx.fillRect(0, 0, 100, 100); // 绘制内容
```

其效果如下，所有绘制内容都被限定到了圆形区域内：

![](https://feishu.cn/file/U9xnbmo4UowHCZxTbyYcy7l4npv)

如果需要取消裁剪区域，可以使用 `ctx.save` 和 `ctx.restore`，在裁剪之前使用 `ctx.save` 保存画布状态，在之后使用 `ctx.restore` 回退画布状态，即可取消裁剪区域。

# 6.2.11 位置判断

如果你需要判断一个点是否处在一个路径内，可以使用如下方法：

```TypeScript
function isPointInPath(x: number, y: number, fillRule?: CanvasFillRule): boolean;
function isPointInPath(path: Path2D, x: number, y: number, fillRule?: CanvasFillRule): boolean;
```

如果你需要处理交互的话，那么此方法会很实用，虽然其性能并不一定有手动判断更好，但是其准确度会更高，而且考虑到交互频率一般不会很高，使用此方法完全合适。示例如下：

```TypeScript
ctx.beginPath();
ctx.rect(0, 0, 100, 100); // 矩形路径
ctx.fill();

ctx.isPointInPath(10, 10); // 在路径内，返回 true
ctx.isPointInPath(110, 10); // 在路径外，返回 false
```

除了这个方法，还可以使用 `ctx.isPointInStroke` 来判断一个点是否在描边内：

```TypeScript
function isPointInStroke(x: number, y: number): void;
function isPointInStroke(path: Path2D, x: number, y: number): void;
```

其中 `lineWidth` 需要通过 `ctx.lineWidth` 设置。例如：

```TypeScript
ctx.beginPath();
ctx.rect(0, 0, 100, 100); // 矩形路径
ctx.lineWidth = 10; // 10 的宽度
ctx.stroke();

ctx.isPointInStroke(1, 1); // 在描边内，返回 true
ctx.isPointInStroke(106, 106); // 在描边外，返回 false
```

# 6.2.12 Pattern 样式

## 基础使用

样板中可以为每个地图设置一个背景图块，这样的话这一层如果什么内容都没有，就会显示成只有背景图块的样子。我们来考虑它是如何实现的。

首先想到的当然是写一个循环，在循环内调用 `drawImage`，如下所示：

```TypeScript
for (let x = 0; x < width; x++) {
    for (let y = 0; y < height; y++) {
        ctx.drawImage(block, x * 32, y * 32, 32, 32);
    }
}
```

但是这样未免太过麻烦，而且由于绘制调用次数多，可能会有额外的绘制开销。因此，我们可以使用浏览器提供的 `CanvasPattern` 接口，这个接口对于这种场景来说非常方便。我们需要使用 `createPattern` 来创建平铺样式，其接口定义如下：

```TypeScript
function createPattern(image: CanvasImageSource, repetition?: string): CanvasPattern;
```

其中第一个参数代表要平铺的图像，可以是图片、画布等内容，第二个参数表示重复方式，即平铺类型，它可以填：

- `repeat`：水平竖直都会平铺，这是默认设置，不填第二个参数的时候就使用此设置。
- `repeat-x`：仅在水平方向上平铺。
- `repeat-y`：仅在竖直方向上平铺。
- `no-repeat`：两个方向都不平铺。

那么我们就可以使用平铺样式来简化上述背景绘制：

```TypeScript
const pattern = ctx.createPattern(block, 'repeat'); // 创建平铺样式
ctx.fillStyle = pattern; // 将平铺样式赋值给 fillStyle
ctx.fillRect(0, 0, 416, 416); // 使用 fillRect 绘制
```

与渐变类似，平铺样式坐标也是基于全局的，不会受到绘制位置的影响。如果需要位移、旋转、放缩等，需要使用线性变换接口：

```TypeScript
ctx.fillStyle = pattern;
ctx.translate(16, 16);
ctx.scale(2, 2);
ctx.fillRect(0, 0, 32, 32);
```

## 注意事项

在创建平铺样式后修改创建样式的图像源是没有效果的，例如将一个画布创建为平铺样式，然后修改画布内容，这时平铺样式绘制的内容不会改变：

```TypeScript
const pattern = ctx.createPattern(patternCanvas, 'repeat'); // 用画布创建一个平铺样式
ctx.fillStyle = pattern;
ctx.fillRect(0, 0, 208, 208); // 使用平铺样式绘制

patternCtx.fillRect(0, 0, 32, 32); // 修改创建样式的画布
ctx.fillRect(0, 0, 208, 208); // 再次使用平铺样式绘制，这时候结果不变
```

与渐变类似，跨上下文使用平铺样式也是未定义行为，不同浏览器行为可能不同，需要避免这种使用方式：

```TypeScript
const pattern = ctx.createPattern(image, 'repeat'); // 使用第一个画布创建样式
ctx2.fillStyle = pattern; // 将样式赋值给第二个画布
```

有一点需要澄清的是，如果你查阅 MDN 文档，它会如此描述 `CanvasPattern`：描述图案的不透明对象。这里的不透明并不是说平铺样式没有不透明度通道，而是说这个对象并不会暴露给用户，即我们不知道对象内部是什么，对象的接口对于我们来说是不透明的，平铺样式自然可以使用透明的图片，并不会使内容变得不透明。

# 6.2.13 文字测量

## 基本概念

我们很难知道一段文字画出来之后其占多大的地方，如果我们需要获取一段文字的宽度、高度等信息，可以使用浏览器提供的 `measureText` 接口：

```TypeScript
function measureText(text: string): TextMetrics;
```

其中 `text` 表示要测量的文字，测量时使用 `ctx.font` 作为字体。

`TextMetrics` 包含很多内容，包括文字的宽度、高度等，我们一个个来看。

- `metrics.width`：描述了这段文字的宽度，单位像素。
- `metrics.actualBoundingBoxAscent` 和 `metrics.actualBoundingBoxDescent`：描述了从文本基线（`ctx.textBaseline` 所描述的位置）到文本最高的顶部及最低的底部的距离。最高的顶部指所有文字中最靠上的位置，最低的底部同理。单位像素，可能是负值。使用图示说明：

<whiteboard token="OUFHwgXgKhU6dubUnREc0Uunnrd"></whiteboard>

- `metrics.actualBoundingBoxLeft` 和 `metrics.actualBoundingBoxRight`：与 `Ascent` 和 `Descent` 类似，描述的是 `ctx.textAlign` 所描述的位置距离文本最左侧和最右侧的距离。单位像素，可能是负值，不再提供图示说明。
- `metrics.fontBoundingBoxAscent` 和 `metrics.fontBoundingBoxDescent`：与 `actual` 类似，但是描述的位置不同，它描述的是字体中包含的所有文字的顶端或底端。这可能不好理解，举例来说，对于 `字` 这个字，它的体积是比字母 `a` 更大的，如果这个字体只包含这两个字，那么 `font` 就会返回 `字` 所对应的距离，而非 `a` 所对应的距离。

我们最常用的也就是这七个属性，其余属性并不常用，这里也不再描述。下面来看一些示例。

## 使用示例

获取文本宽度：

```TypeScript
ctx.font = '16px Verdana'; // 设置测量使用的字体
const metrics = ctx.measureText('这是一段文字'); // 测量文字
metrics.width; // 获取文字宽度
```

获取文本高度，使用 `Ascent` 加上 `Descent`：

```TypeScript
ctx.font = '16px Verdana'; // 设置测量使用的字体
const metrics = ctx.measureText('这是一段文字'); // 测量文字
const height = metrics.actualBoundingBoxAscent + metrics.actualBoundingBoxDescent; // 计算高度
```

## 注意事项

除了 `metrics.width` 外，其余属性都对浏览器版本有一定的要求，兼容性较差，不建议使用，只建议使用 `metrics.width` 这一个属性。如果需要高度，可以直接使用字体大小代替，结果并不会差很多。

# 6.2.14 画布数据

## 基本使用

我们可以通过 `getImageData` 和 `putImageData` 来对画布内容进行像素级的操作。接口声明如下：

```TypeScript
interface ImageData {
    readonly width: number;
    readonly height: number;
    readonly data: Uint8ClampedArray;
}

function getImageData(sx: number, sy: number, sw: number, sh: number, settings?: ImageDataSettings): ImageData;

function putImageData(data: ImageData, dx: number, dy: number): void;
function putImageData(data: ImageData, dx: number, dy: number, sx: number, sy: number, sw: number, sh: number): void;
```

我们需要先使用 `getImageData` 获取数据对象，它的前四个参数表示需要获取的区域，`settings` 参数一般用不到，如果需要可以自行查询：

```TypeScript
const imageData = ctx.getImageData(0, 0, canvas.width, canvas.height);
```

然后我们来看 `imageData` 对象。它的 `width` 和 `height` 属性分别代表裁剪内容的宽度和高度，`data` 是一个一维数字数组，长度为 `width * height * 4`。类型声明中的 `Uint8ClampedArray` 之前没见过，它是一个数字数组，每一项的范围为 `0-255`，至于其他的内容在之后的课程中，参考 <cite doc-id="OzgNwtQZNi6UEBkuT2DcVG8Vnnd" file-type="wiki" title="6.5 类型化数组" type="doc"></cite>。数组以 `R G B A` 的顺序，从左到右，从上到下的顺序排列。例如 `imageData.data[22]` 就表示第 6 个像素的 `B` 通道，即蓝色通道，因为第 6 个像素对应到 `5*4 ~ 6*4` 索引，即 `20~24`，包括 20，不包括 24。

我们可以使用循环来修改每个像素的内容，例如把红色通道去掉：

```TypeScript
const length = imageData.width * imageData.height;
for (let i = 0; i < length; i++) { // 使用一个循环
    imageData.data[i * 4] = 0; // 把每个像素对应的第一个通道设为 0
}
```

之后再使用 `putImageData` 放回画布上，其中 `putImageData` 的第一个参数是数据对象，`dx` `dy` 描述了放到画布的哪个位置，后面的 `sx` 四个参数可选，表示对数据对象裁剪后放到画布上：

```TypeScript
ctx.putImageData(imageData, 0, 0);
```

这样的话画布上的所有内容的红色通道都会变成 0 了。

## 注意事项

使用这个接口相当于使用 CPU 干显卡的事，即 CPU 渲染，因此性能极差，如果不是需要进行图像分析或是极其特殊的场景，非常不建议使用。使用 `drawImage` 绘图性能要显著好于此接口。而如果需要像素级操作，推荐使用后续教程中将会详细讲解的 `WebGL`，而非使用此接口。

# 6.2.15 杂项

## 字体

画布的字体可以设置多个，如果第一个不包含要绘制的文字，那么会自动使用第二个。例如：

```TypeScript
ctx.font = '24px myFont, 16px Arial, 16px Verdana';
```

这样的话，如果 `24px myFont` 字体中不包含要绘制的文字，那么会自动使用 `16px Arial` 作为字体，如果还没有，再尝试使用 `16px Verdana`，如果依然没有，则会使用系统默认字体。

使用 `ctx.measureText` 测量文字时，`metrics.fontBoundingBoxAscent` 及 `metrics.fongBoundingBoxDescent` 只会使用字体列表中的第一个字体，即 `24px myFont`，并不会使用 `16px Arial`，即使要测量的文字包含了 `myFont` 中不包含的文字。

## 其他接口

画布中还有一些接口我们没有讲到，这是因为它们不常用，或者兼容性不好。如果你需要这些接口，可以自行查阅 MDN 文档。
