经过了前两节课的铺垫，我们终于可以开始真正接触 `WebGL2` 了。本节课将会先讲解一些 `WebGL2` 中的必要概念。

# 6.6.1 创建 `WebGL2` 画布

与 `Canvas2D` 类似，我们需要先创建一个 `canvas` 标签，然后调用 `getContext` 方法，不过这里的参数我们需要填写 `webgl2`：

```TypeScript
const canvas = document.createElement('canvas');
const gl = canvas.getContext('webgl2')!; // 获取画布上下文
```

如果浏览器不支持 `WebGL2`，或是之前已经创建了其他的上下文，那么 `getContext` 会返回 `null`，因此这里最后添加了非空断言，从而避免后续类型演算出问题。

获取 `webgl2` 上下文时，可以指定一些配置，常用的包括：

- `alpha`：是否开启透明度通道，默认开启。
- `antialias`：是否开启抗锯齿，默认开启。
- `depth`：开启后，`WebGL2` 将会提供至少 16 位的深度缓冲区，默认开启。深度缓冲区的概念将会在后续讲解。

一般情况下遵循默认设置即可，如果你需要修改设置，可以给 `getContext` 传入第二个参数：

```TypeScript
const gl = canvas.getContext('webgl2', { alpha: false }); // 关闭 alpha 通道
```

# 6.6.2 术语与约定

## 术语

- 源内容：指将要画到画布上的内容。
- 目标内容：指画布上的已有内容。
- NDC 坐标：经过 MVP 变换后的坐标，未经过屏幕坐标变换。

## 约定

- 每个 `RGBA` 通道的值都在 `0 ~ 1` 之间，对于八位色深（大部分显示器的色深），0 对应到 0，1 对应到 255。注意与 `Canvas2D` 区分。

# 6.6.3 混合模式

默认情况下，`WebGL2` 在渲染时会将渲染区域的内容全部覆盖，并且 `alpha` 通道无效。默认设置很可能不符合我们的预期，因此我们在创建画布后设置画布的混合模式。

设置混合模式使用 `gl.enable` 和 `gl.blendFunc` 接口。我们需要先使用 `gl.enable` 开启 `gl.BLEND`，然后使用 `gl.blendFunc` 设置混合模式。一般我们会使用简单 alpha 混合，使用如下代码设置：

```TypeScript
gl.enable(gl.BLEND);
gl.blendFunc(gl.SRC_ALPHA, gl.ONE_MINUS_SRC_ALPHA);
```

## 混合模式公式

混合模式有一个通用的公式：

$$c=(s\times f_s)+(d\times f_d)$$

这里的 $c$ 描述了最终呈现的颜色，$s$ 指源内容的颜色，$d$ 指目标内容的颜色，$f_s,f_d$ 指混合因子，$f_s$ 由 `blendFunc` 的第一个参数指定，$f_d$ 由 `blendFunc` 的第二个参数指定。

`blendFunc` 需要传入两个 `WebGL2` 混合模式常量，下面列一个表来描述常见常量。每个常量对应一个混合因子（$f_s$ 或 $f_d$），因子分为 `R G B A` 四个通道，使用 $R_s,G_s,B_s,A_s$ 描述源内容的 `RGBA` 通道，$R_d,G_d,B_d,A_d$ 描述目标内容的 `RGBA` 通道。列表如下：

| 常量 | `R` 通道 | `G` 通道 | `B` 通道 | `A` 通道 | 文字描述 |
|-|-|-|-|-|-|
| `gl.ZERO` | $0$ | $0$ | $0$ | $0$ | 颜色乘以 0 |
| `gl.ONE` | $1$ | $1$ | $1$ | $1$ | 颜色乘以 1 |
| `gl.SRC_COLOR` | $R_s$ | $G_s$ | $B_s$ | $A_s$ | 颜色乘以源颜色 |
| `gl.ONE_MINUS_SRC_COLOR` | $1-R_s$ | $1-G_s$ | $1-B_s$ | $1-A_s$ | 颜色乘以 1 减源颜色 |
| `gl.DST_COLOR` | $R_d$ | $G_d$ | $B_d$ | $A_d$ | 颜色乘以目标颜色 |
| `gl.ONE_MINUS_DST_COLOR` | $1-R_s$ | $1-G_s$ | $1-B_s$ | $1-A_s$ | 颜色乘以 1 减目标颜色 |
| `gl.SRC_ALPHA` | $A_s$ | $A_s$ | $A_s$ | $A_s$ | 颜色乘以源不透明度 |
| `gl.ONE_MINUS_SRC_ALPHA` | $1-A_s$ | $1-A_s$ | $1-A_s$ | $1-A_s$ | 颜色乘以 1 减源不透明度 |
| `gl.DST_ALPHA` | $A_d$ | $A_d$ | $A_d$ | $A_d$ | 颜色乘以目标不透明度 |
| `gl.ONE_MINUS_DST_ALPHA` | $1-A_d$ | $1-A_d$ | $1-A_d$ | $1-A_d$ | 颜色乘以 1 减目标不透明度 |

以上是常用的混合因子。由此我们可以推断出简单 alpha 混合的混合公式：

$$c=s\times A_s+d\times (1-A_s)$$

这也是 `Canvas2D` 中 `source-over` 混合模式所使用的混合因子。

上面这些混合因子可以自由混合，例如：

```TypeScript
gl.enable(gl.BLEND);
gl.blendFunc(gl.SRC_COLOR, gl.SRC_ALPHA);
```

就会将混合公式设为：

$$c=s\times (R_s,G_s,B_s,A_s)+d\times A_s$$

# 6.6.4 数据缓冲区

`WebGL2` 使用显卡渲染，因此我们不能使用传统的方法来给它传递参数，因为显卡有独立的内存区域，与 CPU 并不共享，因此我们需要将数据通过缓冲区传递给显卡，之后再进行渲染操作。

`WebGL2` 是一个巨大的状态机，使用缓冲区传递数据时需要先设定我要传输什么内容，确定好传输状态，然后再进行传输。

## 创建缓冲

创建缓冲使用 `createBuffer` 接口：

```TypeScript
function createBuffer(): WebGLBuffer;
```

直接调用创建即可：

```TypeScript
const buffer = gl.createBuffer();
```

返回值的 `WebGLBuffer` 不包含任何接口，因此 `ts` 会将它识别为与空对象相同，从而导致潜在的类型错误，需要注意。

## 绑定缓冲区

接下来我们需要把创建的缓冲区绑定至 `WebGL2`，使用 `bindBuffer` 接口：

```TypeScript
function bindBuffer(target: GLenum, buffer: WebGLBindBuffer): void;
```

这里的 `target` 指要绑定至哪个缓冲区，`buffer` 指的是刚刚用 `createBuffer` 创建的缓冲。这个方法的重点是第一个参数 `target`，在不同场景下要填入不同的值。`WebGL2` 一共给我们提供了八个缓冲区，我们可以在这八个缓冲区中操作修改缓冲数据。不过由于我们压根还没有学各种场景，因此我们这里只介绍一种用法，绑定至 `gl.ARRAY_BUFFER` 缓冲区：

```TypeScript
const buffer = gl.createBuffer();
gl.bindBuffer(gl.ARRAY_BUFFER, buffer);
```

这样，我们刚刚创建的缓冲就被绑定在了 `gl.ARRAY_BUFFER` 上，之后再去操作 `gl.ARRAY_BUFFER`，我们操作的就是刚刚创建的 `buffer` 缓冲。至于其他的七种缓冲区，我们之后再去说，现在还讲不了。

## 缓冲区操作

绑定缓冲区之后，我们需要用 `bufferData` 或 `bufferSubData` 为缓冲区赋值。

### `bufferData`

`bufferData` 一般用于重新给缓冲区赋值，它会为缓冲区重新分配内存并赋值，因此速度相对较慢，一般只会在内容长度修改或者第一次赋值时使用。它的用法如下：

```TypeScript
function bufferData(target: GLenum, size: number, usage: GLenum): void;
function bufferData(target: GLenum, src: ArrayBuffer | TypedArray, usage: GLenum): void;
function bufferData(target: GLenum, src: ArrayBuffer | TypedArray, usage: GLenum, srcOffset: number, length: number): void;
```

三种用法分别描述如下：

1. 给缓冲区设置长度为 `size`（字节长度），并全部填充为 0。
2. 给缓冲区赋值为 `src`，字节长度也设为 `src` 对应的字节长度。
3. 给缓冲区赋值为 `src`，从 `src` 的第 `srcOffset` 索引位置开始读取（非字节长度），读取 `length` 个数据（非字节长度），字节长度设为 `length * byte`，即 `length` 乘以单个数据的字节数。

使用时，第一个参数 `target` 填写上述绑定缓冲区的 `target`，例如我们刚刚绑定了 `gl.ARRAY_BUFFER` 缓冲区，这里的 `target` 也要填写 `gl.ARRAY_BUFFER`。

`usage` 描述了缓冲区数据的使用场景，`WebGL2` 会根据使用场景进行优化。常用的 `usage` 包括下面这些：

- `gl.STATIC_DRAW`：缓冲区的内容可能经常使用，而基本不会被更改。此操作用于给缓冲区赋值。
- `gl.DYNAMIC_DRAW`： 缓冲区的内容可能经常被使用，并且经常更改。此操作用于给缓冲区赋值。
- `gl.STREAM_DRAW`：缓冲区的内容可能不被经常使用，而且基本不会被更改。此操作用于给缓冲区赋值。

例如，我们需要传入一个不被经常修改而可能被经常使用的缓冲，可以这么写：

```TypeScript
const src = new Uint8Array([1, 2, 3, 4, 5, 6, 7, 8]);
const buffer = gl.createBuffer();
gl.bindBuffer(gl.ARRAY_BUFFER, buffer);
gl.bufferData(gl.ARRAY_BUFFER, src, gl.STATIC_DRAW);
```

### `bufferSubData`

`bufferSubData` 用于更新缓冲区的内容，它不会重新分配内存，因此性能也会比 `bufferData` 更好。它的用法如下：

```TypeScript
function bufferSubData(target: GLenum, offset: number, srcData: ArrayBuffer | TypedArray): void;
function bufferSubData(target: GLenum, offset: number, srcData: ArrayBuffer | TypedArray, srcOffset: number, srcLength?: number): void;
```

它的用法与 `bufferData` 类似，`target` 描述要赋值的缓冲区，两种用法说明如下：

1. 从缓冲区的 `offset` 字节开始赋值，赋值为 `srcData`。
2. 从缓冲区的 `offset` 字节开始赋值，赋值为 `srcData`，读取 `srcData` 时从 `srcOffset` 索引开始（非字节长度），读取 `srcLength` 长度（非字节长度）。

示例如下：

```TypeScript
const src = new Uint8Array([1, 2, 3, 4, 5, 6, 7, 8]);
const buffer = gl.createBuffer();
gl.bindBuffer(gl.ARRAY_BUFFER, buffer);
gl.bufferData(gl.ARRAY_BUFFER, src, gl.DYNAMIC_DRAW); // usage 改为 DYNAMIC_DRAW
// 此时缓冲区为 0x01 0x02 0x03 0x04 0x05 0x06 0x07 0x08
const src2 = new Uint16Array([0xABCD, 0x7890]);
gl.bufferSubData(gl.ARRAY_BUFFER, 2, src2);
// 此时缓冲区为 0x01 0x02 0xCD 0xAB 0x90 0x78 0x07 0x08
```

### 常见问题

1. 既然 `target` 最多只有八个，那我是不是只能绑定八个缓冲区？

答：是的。我们一般只会使用两三个，如果一个 `target` 有多个缓冲区，我们会一个个 `bindBuffer` 再 `bufferData`。

1. 为什么缓冲区赋值要这么复杂？

答：因为这是在操作显卡，我们需要在 CPU 代码里面操作显卡，告诉显卡数据是什么，因此操作起来与 CPU 变量的赋值读取完全不同。这些操作都是必要的。

## 删除缓冲区

如果一个缓冲区数据不再会被使用，那么需要删除它，使用 `gl.deleteBuffer` 接口：

```TypeScript
function deleteBuffer(buffer: WebGLBuffer): void;
```

示例如下：

```TypeScript
const buffer = gl.createBuffer();
gl.deleteBuffer(buffer); // 删除缓冲区数据
```

# 6.6.5 顶点

为了让 `WebGL2` 能画出来东西，我们必须告诉他要在哪些地方画东西，这一操作是通过顶点完成的。

我们会有这些绘制方法：画点、画线、画平面。我们最常用的是画平面，画点和画线很少用到，因为它们都可以通过画平面实现，我们也不再讲解画点和画线。

## 顶点数组

由于物体有多个顶点，因此我们使用数组来描述。一般来说，一个顶点可能会有两个、三个坐标，分别对应二维和三维。

定义顶点数组时，我们直接把坐标按照 `x` `y` `z` 的顺序排列在 `Float32Array` 类型化数组中即可。如果顶点是二维的，只需填写 `x` `y`，两个一组，如果是三维的，则需要三个一组。例如：

```TypeScript
const vertex1 = new Float32Array([1, 1, 1, 2, 2, 2, 3, 3, 3]); // 三个点分别是 (1,1,1) (2,2,2) (3,3,3)
const vertex2 = new Float32Array([1, 1, 2, 2, 3, 3, 4, 4]); // 四个点分别是 (1,1) (2,2) (3,3) (4,4)
```

我们会发现一个问题，我们如何区分顶点是二维的还是三维的呢？这个问题暂时无法解答，需要留到后面的课程。

## 赋值到缓冲区

接下来，我们就可以按照 5.6.4 中的方式给缓冲区赋值了，代码如下：

```TypeScript
const vertex = new Float32Array([1, 1, 1, 2, 2, 2, 3, 3, 3]);
const buffer = gl.createBuffer();
gl.bindBuffer(gl.ARRAY_BUFFER, buffer);
gl.bufferData(gl.ARRAY_BUFFER, vertex, gl.STATIC_DRAW);
```

我们定义逆时针三角形为顺向三角形，顺时针三角形为逆向三角形。

我们考虑一个正方体，它一共有六个面，共十二个三角形（正方形面由两个三角形组成），此时当我们看向正方体时，最多只能看到三个面六个三角形，剩余的三角形看不见。这时如果还对它们进行渲染，就会额外产生不必要的开销，因此我们需要面剔除的功能。

# 6.6.6 深度检测

我们之前提到过 `z` 坐标超出 `-1 ~ 1` 范围的内容会被裁剪掉，这说明 `z` 坐标会有裁剪功能。但是除了裁剪，`z` 坐标还可以描述深度，即距离观察者有多远。

经过投影变换后，靠近观察者的物体 `z` 坐标更大，远离观察者的物体 `z` 坐标更小，因此我们可以通过 `z` 坐标来描述物体之间的遮挡关系，`z` 坐标大的会遮挡 `z` 坐标小的。通过判断 `z` 坐标，我们可以判断一个物体是否被遮挡，从而决定它是否应该被渲染，被遮挡就不渲染，不被遮挡就渲染，从而提高渲染性能。这一行为称为深度检测。

我们一般会使用 NDC 坐标进行推理，而在实际渲染时，深度检测是在屏幕坐标上进行的。因此在设定深度检测模式时，判断方式会与我们的推理刚好相反。参考 <cite doc-id="Xx1HwtQboiPUlRkE7xTc1hpanzc" file-type="wiki" title="6.4 WebGL2 数学基础" type="doc"></cite> 5.4.10 最后对屏幕变换的描述。

在深度检测中，如果判断一个物体需要被渲染，它会被叫做通过深度测试。

在 `WebGL2` 中，使用 `gl.enable` 开启深度检测：

```TypeScript
gl.enable(gl.DEPTH_TEST);
```

使用 `gl.depthFunc` 调整深度检测模式，常见的有这些模式：

- `gl.NEVER`：从不通过，即从不渲染
- `gl.LESS`：深度值小于当前深度值的通过，`z` 坐标小的覆盖大的。在 NDC 坐标下，就是 `z` 坐标大的覆盖小的。这是默认设置，也是常用设置。
- `gl.LEQUAL`：深度值小于等于当前深度值的通过，`z` 坐标小的覆盖大的，但是还包含相同的场景。在 NDC 坐标下，就是 `z` 坐标大的覆盖小的。

设置示例如下：

```TypeScript
gl.enable(gl.DEPTH_TEST);
gl.depthFunc(gl.LEQUAL);
```

# 6.6.7 着色器概念

着色器是显卡能够直接执行的代码，分为顶点着色器和片段着色器两种。顶点着色器用于确定绘制顶点，片段着色器用于确定每个像素的颜色。

由于着色器内容比较复杂，本节课暂且不讲着色器代码如何编写以及其含义，只讲解着色器的基本概念以及如何编译链接着色器。

## 顶点着色器

顶点着色器英文是 `vertex shader`，用来确定绘制顶点。具体来说，它用于将世界坐标下的顶点位置映射至 NDC 坐标。

例如，给定一个立方体，它一共包含 12 个三角形，使用 `gl.TRIANGLES` 连接方式时需要 36 个顶点，那么 `WebGL2` 会依次将这 36 个顶点传入，经过着色器计算后，得到对应的 36 个 NDC 坐标。这样，再根据连接方式，`WebGL2` 就可以确定需要在哪些地方渲染了。

## 片段着色器

片段着色器英文是 `fragment shader`，用来确定每个像素的颜色。有时还称为片元着色器或像素着色器。

当确定了顶点之后，`WebGL2` 会对顶点范围内的所有像素遍历，并调用片段着色器得到这一像素的颜色。

## 创建着色器

着色器代码使用字符串定义，并通过 `createShader` 与 `shaderSource` 传递。二者的类型声明如下：

```TypeScript
function createShader(type: GLenum): WebGLShader;
function shaderSource(shader: WebGLShader, source: string): void;
```

首先定义一个着色器代码（暂时不用管代码是干什么的）：

```TypeScript
// 顶点着色器
const vs = /* glsl */ `#version 300 es
precision highp float;

in vec4 a_position;
uniform mat4 u_matrix;

void main() {
    gl_Position = u_matrix * a_position;
}
`;
// 片段着色器
const fs = /* glsl */ `#version 300 es
precision highp float;

out vec4 outColor;

void main() {
    outColor = vec4(1.0, 1.0, 1.0, 1.0);
}
`;
```

然后分别创建顶点着色器与片段着色器对象：

```TypeScript
const vsShader = gl.createShader(gl.VERTEX_SHADER); // 创建顶点着色器
const fsShader = gl.createShader(gl.FRAGMENT_SHADER); // 创建片段着色器
```

然后将着色器代码传递给着色器对象：

```TypeScript
gl.shaderSource(vsShader, vs); // 顶点着色器
gl.shaderSource(fsShader, fs); // 片段着色器
```

# 6.6.8 `WebGL2` 程序

`WebGL2` 程序存储了顶点着色器与片段着色器代码，包含了程序的状态信息，可以被显卡执行。

## 创建程序

创建程序使用 `gl.createProgram`，类型声明如下：

```TypeScript
function createProgram(): WebGL2Program;
```

示例如下：

```TypeScript
const program = gl.createProgram();
```

## 编译着色器

程序创建完成之后不能直接运行，因为我们还没有给它添加着色器，添加之前我们需要先编译着色器，使用 `gl.compileShader` 接口，类型声明如下：

```TypeScript
function compileShader(shader: WebGLShader): void;
```

示例如下：

```TypeScript
const vsShader = gl.createShader(gl.VERTEX_SHADER); // 创建顶点着色器
const fsShader = gl.createShader(gl.FRAGMENT_SHADER); // 创建片段着色器
gl.shaderSource(vsShader, vs); // 顶点着色器代码
gl.shaderSource(fsShader, fs); // 片段着色器代码
gl.compileShader(vsShader); // 编译顶点着色器
gl.compileShader(fsShader); // 编译片段着色器
```

## 添加着色器

着色器编译完成后，我们还需要给程序添加着色器，使用 `attachShader` 接口：

```TypeScript
function attachShader(program: WebGLProgram, shader: WebGLShader);
```

示例如下：

```TypeScript
gl.attachShader(program, vsShader); // 顶点着色器
gl.attachShader(program, fsShader); // 片段着色器
```

着色器与程序是分开的两个概念，因此多个程序可以共用一个着色器，例如共用一个顶点着色器，这在一些场景下非常方便。

## 链接着色器程序

最后我们需要链接着色器程序，让程序能够在显卡上运行，使用 `linkProgram` 即可：

```TypeScript
function linkProgram(program: WebGLProgram): void;
```

下面的例子将创建着色器、编译着色器、创建程序等放在一起：

```TypeScript
const vsShader = gl.createShader(gl.VERTEX_SHADER); // 创建顶点着色器
const fsShader = gl.createShader(gl.FRAGMENT_SHADER); // 创建片段着色器
gl.shaderSource(vsShader, vs); // 顶点着色器代码
gl.shaderSource(fsShader, fs); // 片段着色器代码
gl.compileShader(vsShader); // 编译顶点着色器
gl.compileShader(fsShader); // 编译片段着色器

const program = gl.createProgram(); // 创建着色器程序
gl.attachShader(program, vsShader); // 添加顶点着色器
gl.attachShader(program, fsShader); // 添加片段着色器
gl.linkProgram(program); // 链接着色器程序
```

## 删除程序与着色器

如果一个程序和着色器不会再被使用到，需要使用 `gl.deleteProgram` 和 `gl.deleteShader` 删除。它们的定义如下：

```TypeScript
function deleteProgram(program: WebGLProgram): void;
function deleteShader(shader: WebGLShader): void;
```

示例如下：

```TypeScript
gl.deleteProgram(program); // 删除程序
gl.deleteShader(vsShader); // 删除顶点着色器
gl.deleteShader(fsShader); // 删除片段着色器
```

# 6.6.9 内置缓冲区

注意，本节与 5.6.4 的数据缓冲区不同。

这里的缓冲区是指 `WebGL2` 内置的一些缓冲区，包括颜色缓冲区、深度缓冲区等。

## 颜色缓冲区

渲染时，`WebGL2` 会先把内容绘制到颜色缓冲区，然后设备的显示器读取颜色缓冲区的内容并显示出来。一般来讲，颜色缓冲区至少是双缓冲，内容会渲染至第一层缓冲，然后再推送给第二层缓冲，最后由显示器读取第二层缓冲。这么做是为了保证渲染完成前不会被显示器读取并显示出来，避免出现画面撕裂或是只渲染了一部分的情况。

一般来说，我们在渲染内容前，需要先清空颜色缓冲区。我们需要使用 `gl.clearColor` 设置清空为什么颜色，再调用 `gl.clear` 清空缓冲区。二者的类型声明如下：

```TypeScript
function clearColor(r: number, g: number, b: number, a: number): void;
function clear(bit: GLbitfield): void;
```

示例如下：

```TypeScript
gl.clearColor(0, 0, 0, 0); // 清空为透明色
gl.clear(gl.COLOR_BUFFER_BIT); // 清空颜色缓冲区
```

## 深度缓冲区

深度缓冲区是在深度检测时用到的。在渲染时，一个像素的深度值会与深度缓冲区的值进行比较，如果满足条件（比如 `gl.LESS`），那么会更新深度缓冲区，并渲染这个像素，否则就不会做渲染。而在比较时，我们需要为深度缓冲区设定一个初始值，否则像素就不知道跟谁比较了。

由于深度值越大越远离观察者，因此我们一般将深度缓冲区设为 1。使用 `clearDepth` 设置：

```TypeScript
function clearDepth(depth: number): void;
```

示例如下：

```TypeScript
gl.clearDepth(1); // 深度缓冲区设为 1，这一步仅是配置项，不会进行清理
gl.clear(gl.DEPTH_BUFFER_BIT); // 清空深度缓冲区并设为 1
```

而在渲染前，我们一般是需要同时清空深度缓冲区和颜色缓冲区的，我们可以这么写：

```TypeScript
gl.clearColor(0, 0, 0, 0);
gl.clearDepth(1);
gl.clear(gl.COLOR_BUFFER_BIT | gl.DEPTH_BUFFER_BIT); // 将两个清空项用按位或连接，就可以同时清理
```
