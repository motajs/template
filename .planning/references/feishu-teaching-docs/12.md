# 5.2.1 字符串字面量

本小节对字符串字面量的声明做复习，并对之前课程可能遗漏的内容做补充。

## 普通字符串

普通字符串使用单引号或双引号声明，二者没有任何区别，我们建议使用单引号，因为输入的时候不需要按 Shift 键：

```TypeScript
'abc'; // 单引号
"abc"; // 双引号，与单引号没有任何区别
```

单引号声明的字符串内不允许出现单引号，双引号同理：

```TypeScript
'I'm happy'
"He says "...""
```

这样的话引号会就近匹配，于是就会引起错误。

不过单引号内可以出现双引号，双引号内也可以出现单引号：

```TypeScript
"I'm happy"; // 没有问题
'He says "..."'; // 没有问题
```

如果你真的要在单引号内写单引号，双引号内写双引号，可以使用转义字符：

```TypeScript
'I\'m happy';
"He says \"...\"";
```

## 模板字符串

模板字符串使用反引号 \` 声明，反引号内可以换行：

```TypeScript
`第一行
第二行
第三行`;
```

模板字符串在换行时会保留缩进：

```TypeScript
`第一行
    第二行，前面空四格
`;
```

模板字符串内可以使用 `${}` 嵌入表达式，内容会自动转为字符串。

```TypeScript
`数字：${123}，字符串：${'abc'}，布尔值：${true}`;
```

## ASCII 解析

字符串内允许使用 `\x` 来声明 ASCII 码。例如字母 `a` 对应的 ASCII 码为 61，其十六进制为 ，那么可以这么写：

```TypeScript
'\x61'; // 字母 a
"\x61"; // 字母 a
`\x61`; // 字母 a
```

但是注意不能动态拼接：

```TypeScript
'\x' + '97'; // 会报错！
`\x${97}`; // 会报错！
```

# 5.2.2 Unicode 码

> 这一节相对不那么重要，但是如果想要深入理解字符串的话，这一节是必看的。如果只是做一些非常简单的工作，这一节不看也行。

Unicode 码是全球通用的字符码，包含了目前世界上的几乎所有文字和字符。它包含基础平面与若干额外平面，基础平面中多是常见的字符，例如英文字符、中日韩字符（CJK字符）、部分常用的 `emoji` 等。而额外平面则会包含一些不那么常用的字符，例如一些罕见的古文字、部分 `emoji` 等。

对于基础平面的字符，会使用四个十六进制数表示，对于额外平面的字符，会使用五个十六进制数表示。我们称基础平面和额外平面的单个字符叫做码元。

Unicode 码兼容 ASCII 码，因此 ASCII 可以直接转换为 Unicode。

下面讲一下如何在 js 中使用 Unicode 码。

## Unicode 解析

在字符串中以 `\u` 开头，并紧跟着四个十六进制数，或是跟上花括号，花括号内写上一至五个十六进制数即可，注意 `\u` 后面不加花括号的话必须跟四个，否则会报错：

```TypeScript
'\u0061'; // 字母 a
"\u0061"; // 字母 a
`\u0061`; // 字母 a
'\u{0061}'; // 字母 a
"\u{61}"; // 字母 a
```

来看一个中文的例子，以汉字 `魔` 为例，它的 unicode 码为 `9b54`，因此可以这么写：

```TypeScript
'\u9b54'; // 汉字 魔
"\u9B54"; // 汉字 魔
'\u{9B54}'; // 汉字 魔
```

额外屏幕的 unicode 比较少见，一般是 emoji 或者特殊符号。例如对于一个神秘的表意文字 `𐂣`，其 Unicode 码为 `100a3`，如果我们如果使用 Unicode 声明它，那么需要使用 `\u{xxxxx}` 的形式，不能用 `\uxxxxx` 的形式：

```TypeScript
'\u{100a3}'; // 𐂣
'\u100a3'; // ည3，\u100a 被视为了 ည，后面的 3 单独就是一个字符
```

与 ASCII 同样，Unicode 也不能动态组合：

```TypeScript
'\u' + '0061'; // 会报错！
```

## 在代码中使用 Unicode

除了字符串内，代码中也可以使用 Unicode，例如：

```TypeScript
const \u{61} = 10; // 将 10 赋给常量 a
```

这个东西不太可能见得到，没必要记住，知道能这么干就行。

## 特殊 Unicode

除了基础平面和额外平面，Unicode 中还包含一些特殊行为的字符，它们要求多个码元组合到一起。这种字符多是 `emoji`，例如对于 emoji 😄，它由两个码元 `\uD83D\uDE04` 组成。

要判断是否要组合，需要看第一个码元是什么，如果第一个码元是处在 `\uD800` 和 `\uDBFF` 之间的话，就会和后续码元一起解析组合。例如 `\uD842\uDFB7` 会解析出 `𠮷` 字，`\uD83D\uDE04` 会解析出 😄 等。

实际上 `emoji` 可以使用一系列连续的 Unicode 码组合到一起形成不同的颜色，甚至是直接组合。有时候我们看到有机器人可以把几个 `emoji` 组合成一个新的 `emoji`，实际上内部可能就是 Unicode 自身组合做到的。

除了上述组合方式，一些普通字符也可以与其他 Unicode 组合，例如数字和星号井号加上 `\ufe0f\u20e3` 就可以把它变成数字键帽 `emoji`：

```TypeScript
[0, 1, 2, 3, 4, 5].map(num => num + '\ufe0f\u20e3');
// ["0️⃣", "1️⃣", "2️⃣", "3️⃣", "4️⃣", "5️⃣"] 
```

这些内容做了解即可，如果想深入了解可以看看这篇知乎文章：https://zhuanlan.zhihu.com/p/407013219

# 5.2.3 字符串拼接

字符串拼接有两种常用方法，第一种方法是使用 `concat` 接口，第二种方法是使用 + 运算符。

## `+` 运算符

多个字符串直接使用 + 连接就可以拼接在一起：

```TypeScript
'abc' + 'def'; // 'abcdef'
'123' + '456' + '789'; // '123456789'
```

## `concat` 接口

`concat` 是字符串的一个方法，允许将多个字符串与一个字符串拼接到一起。其类型声明如下：

```TypeScript
function concat(...strs: string[]): string;
```

例如：

```TypeScript
'abc'.concat('def'); // 'abcdef'
'abc'.concat('def', 'ghi'); // 'abcdefghi'
'123'.concat('456', '789', '123'); // '123456789123'
```

这种方法由于写起来会比较麻烦，所以使用场景较少。多数情况下我们会使用 + 运算符连接字符串。

## `join` 接口

`join` 是数组的一个方法，可以把数组的每一项转换成字符串并且使用指定字符串连接在一起。这一接口已经在数组这一节中讲过，这里仅做回忆。

```TypeScript
[1, 2, 3].join('+'); // 1+2+3
[1, 2, 3].join(); // 123
```

`join` 方法多在不定长内容字符串拼接以及内容较多时使用，其使用场景较少，不过还是需要了解这一接口的。

关于 `join` 方法的更多其他特性，我们会在数组补充中再做讲解。

# 5.2.4 字符串性能与规范问题

虽然字符串的性能很好，但是相比于数字类型和布尔值，它就相当慢了，因为字符串实际上相当于一个字符数组，数组操作并不快。因此我们建议非必要时不使用字符串，尤其是在 `Map` 映射中。

我们有时还会使用正则表达式匹配字符串，这写起来非常方便，但是正则表达式的速度其实很慢，在一些简单场合当然可以使用，而在对性能要求较高的场合就会严重拖慢速度了。

例如，在魔塔中，我们可能会建立一个映射，以图块 `id` 为键，其他内容为值，其实这么做并不好，更好的做法是以图块数字为键，其他内容为值，数字做映射要远比更快。

而如果要罗列一系列数据，更建议用枚举，例如对于朝向，使用 `left` `right` 等字符串就是不好的写法，而使用枚举就是更好的写法：

```TypeScript
const enum FaceDirection {
    Unknown,
    Left,
    Up,
    Right,
    Down,
    LeftUp,
    RightUp,
    LeftDown,
    RightDown
}
```

一般我们使用字符串只有如下场景：

- 要给用户展示文字
- 必须使用字符串存储的数据，如用户名、助记符等
- 浏览器内部接口要求必须使用字符串

其他场景下很少会有使用字符串的需求。

# 5.2.5 字符串长度

可以通过字符串的 `length` 属性获取字符串的长度：

```TypeScript
'abcde'.length; // 5
'123'.length; // 5
```

字符串的 `length` 属性是只读属性，不可修改，如果强行赋值，那么会报错。

需要注意的是，字符串的长度并不一定等于字符数量，例如使用 5.2.2 中讲到的组合 Unicode 时，这些文字可能会包含多个码元，那么 `length` 属性就会计数多次：

```TypeScript
'😄'.length; // 2
```

# 5.2.6 字符串索引

## 使用索引运算符

与数组类似，字符串可以直接使用方括号索引：

```TypeScript
'abcde'[3]; // 'd'
'12345'[2]; // '3'
```

需要注意的是，字符串的索引是只读的，不可以修改，如果使用等号赋值，那么会赋值失败，同时不会报任何错误：

```TypeScript
let a = 'abcde';
a[1] = 'f'; // 这句赋值会返回 'f'，是赋值运算符的返回值
a; // 但是这里还是 'abcde'
```

这是因为字符串并不是引用类型，它是一个字面量类型，当创建完毕后就无法修改了，除非创建一个新的字符串。如果需要修改字符串的某一项，可以使用 `slice` 方法（在后文讲解）：

```TypeScript
const a = 'abcde';
a.slice(0, 1) + 'f' + a.slice(2); // 'afcde'
```

但是这种行为非常少见，应该不会遇到这种需求。

## 使用 `at` 接口

与数组类似，字符串也有 `at` 方法，它的功能与数组也类似，在直接索引的基础上允许填入负数从结尾开始索引：

```TypeScript
'abcde'.at(-1); // 'e'
'abcde'.at(4); // 'e'
```

## 使用 `charAt` 接口

`charAt` 接口与直接使用索引运算符索引基本一致，直接填入索引：

```TypeScript
'abcde'.charAt(0); // 'a'
'abcde'.charAt(4); // 'e'
```

如果超出了字符串的范围，那么会返回一个空字符串：

```TypeScript
'abcde'.charAt(-1); // ''
'abcde'.charAt(5); // ''
```

如果不填写参数，会获取索引为 0 的字符：

```TypeScript
'abcde'.charAt(); // 'a'
```

## 特殊行为

> 这一节简单了解即可，基本上一辈子碰不到

对于 5.2.4 中讲到的占据多个码元的字符，使用如上三个方式都不会获取到完整字符，而是会获取到对应字符的两个码元：

```TypeScript
'😄'[0]; // '\uD83D'
'😄'[1]; // '\uDE04'
'1️⃣'.charAt(0); // '1'
'1️⃣'.charAt(1); // '\uFE0F'
'1️⃣'.at(2); // '\u20E3'
```

要获取码元数量是 2 的字符，可以使用迭代器：

```TypeScript
const arr = [...'😄123']
arr[0]; // '😄'
arr[1]; // '1'
```

但是对于码元数量超过 2 的字符，依然不能正确识别：

```TypeScript
[...'1️⃣']; // ['1', '️', '⃣']
```

对于这种码元数量超过 2 的字符并没有简单的方式获取到，但是这种场景极其少见，需要使用相应的第三方库实现，我们也不再讲解了。

# 5.2.7 字符串遍历

一般使用 `for` 循环遍历：

```TypeScript
const str = 'abcde';
for (let i = 0; i < str.length; i++) {
    console.log(str[i]); // 依次输出 'a' 'b' 'c' 'd' 'e'
}

for (const char of str) {
    console.log(char); // 依次输出 'a' 'b' 'c' 'd' 'e'
}
```

# 5.2.8 字符串处理接口

下面讲解一下字符串中常用的处理接口。

## 去除空格

去除空格使用 `trim` 系列接口，`trim` 系列包含 `trim` `trimStart` `trimEnd` 三个接口，作用分别是去除字符串前后的空格，去除字符串前的空格，去除字符串后的空格：

```TypeScript
'   abcde   '.trim(); // 'abcde'
'   abcde   '.trimStart(); // 'abcde   '
'   abcde   '.trimEnd(); // '   abcde'
```

## 大小写转换

大小写转换会使用 `toLowerCase` 和 `toUpperCase` 接口：

```TypeScript
'abcde'.toUpperCase(); // 'ABCDE'
'ABCde'.toLowerCase(); // 'abcde'
```

## 字符串裁剪

字符串裁剪常用 `slice` 和 `substring`，二者几乎没有区别，我们建议使用 `slice` 而不是 `substring`。`slice` 的定义如下：

```TypeScript
function slice(start?: number, end?: number): string;
```

- `start`: 裁剪起始索引，裁剪结果包含此索引。
- `end`：裁剪终止索引，裁剪结果不包含此索引。

这两个参数都可以填负数，如果填负数的话会从结尾开始索引。如果起始索引大于终止索引，那么会返回一个空字符串。示例如下：

```TypeScript
'abcde'.slice(); // 'abcde'
'abcde'.slice(1); // 'bcde'
'abcde'.slice(1, 3); // 'bc'
'abcde'.slice(-2, -1); // 'e'
'abcde'.slice(4, 1); // ''
```

而对于 `substring`，如果起始索引大于终止索引，那么会交换两者，并不会返回空字符串，且负数参数视为 0：

```TypeScript
'abcde'.substring(4, 1); // 'bcd'
'abcde'.substring(-2, -1); // ''，负数参数视为 0，所以相当于 substring(0, 0)
```

## 前后填充

可以使用 `padStart` 和 `padEnd` 在字符串前后填充内容，它们的类型声明一样：

```TypeScript
function padStart(targetLength: number, padString?: string): string;
```

当字符串长度大于等于 `targetLength` 时，会将字符串原样返回。如果字符串长度小于 `targetLength`，那么会在前方（`padStart`）或后方（`padEnd`）填充 `padString` 字符直到字符串长度等于 `targetLength`，然后将填充后的字符串返回。如果不填 `padString`，则视为空格。

示例如下：

```TypeScript
'abc'.padStart(5, 'a'); // 'aaabc'
'abc'.padEnd(5, 'a'); // 'abcaa'
```

## 字符串重复

使用 `repeat` 接口重复一个字符串若干次：

```TypeScript
function repeat(count: number): string;
```

`count` 表示重复次数。例如：

```TypeScript
'abc'.repeat(3); // 'abcabcabc'
```

## 字符串分割

使用 `split` 将字符串按照指定内容将字符串分割成一个数组。其类型声明如下：

```TypeScript
function split(pattern: string | RegExp, limit?: number): string[];
```

- `pattern`：指字符串应该在哪里分割，可以填字符串，说明按照这个字符串分割；也可以填正则表达式，会按照匹配到的正则分割。
- `limit`：最多分割几次，在分割这么多次之后忽略后面的内容。

文字描述可能不那么直观，看例子：

```TypeScript
'abc|bcd|def'.split('|'); // ['abc', 'bcd', 'def']
'abc|bcd|def'.split('|', 2); // ['abc', 'bcd']，第二个 '|' 后面的内容被忽略
'abc,bcd|def/efg\fgh'.split(/[,|/\\]/); // ['abc', 'bcd', 'efg', 'fgh]，使用正则表达式分割
```

# 5.2.9 字符串判断

字符串判断分为相等、大于、小于、包含、开头、结尾几种类型。

## 字符串判等

字符串判等使用等于运算符 `===`：

```TypeScript
'abc' === 'abc'; // true
'abc' === 'bcd'; // false
```

当然使用弱等于 `==` 也行，但是弱等于在几乎所有情况下都不推荐使用。

## 大小比较

字符串之间可以使用 `>` `<` `>=` `<=` 比较大小，比较时会比较第一位字符的 Unicode 值，如果相等再比较后续的字符。例如：

```TypeScript
'cde' > 'b'; // true，第一个字符 c 的 Unicode 大于 b
'bbb' > 'bab'; // true，第二个字符 b 的 Unicode 大于 a
```

## 包含判断

包含判断可以使用 `includes` `indexOf` `lastIndexOf` 三个方法，与数组的用法基本一致。

`includes` 用于判断是否包含一个字符串：

```TypeScript
function includes(search: string, position?: number): boolean;
```

- `search`：要判断是否包含的字符串。不能填正则表达式。
- `position`：从指定索引开始搜索，不填表示从头开始搜索。

`indexOf` 和 `lastIndexOf` 用于搜索指定字符串在当前字符串中的索引，它们的类型声明一致：

```TypeScript
function indexOf(search: string, position?: number): number;
```

- `search`：要判断包含的字符串。不能填正则表达式。
- `position`：对于 `indexOf`，表示从指定索引开始向后搜索；对于 `lastIndexOf`，表示从指定索引开始向前搜索。不论 `indexOf` 还是 `lastIndexOf`，这里的从指定索引开始搜索表示 `search` 的第一个字符从被搜索字符串的指定索引开始搜索，也就是：

<whiteboard token="SjBAwBZPthZ9gebOeWFczXYunQf"></whiteboard>

对于这两个接口，如果搜索到了，那么会返回对应的索引，否则返回 `-1`。

三个接口的示例如下：

```TypeScript
'abcdefg'.includes('abc'); // true
'abcdefg'.includes('abc', 1); // false，从索引 1 开始搜索，搜索不到
'abcdefg'.indexOf('cde'); // 2
'abcdefg'.indexOf('cde', 3); // -1，搜索不到
'abcdefg'.lastIndexOf('cde'); // 2，依然是从前往后数的索引，而不是从后往前数的索引
'abcdefg'.lastIndexOf('cde', 2); // 2，从索引 2 开始向前搜索
```

## 开头结尾判断

开头结尾判断使用 `startsWith` 和 `endsWith`，它们会判断字符串是否以指定字符串开头或结尾：

```TypeScript
function startsWith(search: string, position?: number): boolean;
```

- `search`：要判断的字符串。不能填正则表达式。
- `position`：字符串判断位置。对于 `startsWith`，表示第一个字符所在位置索引，对于 `endsWith`，表示最后一个字符所在位置索引+1，注意与 `indexOf` 和 `lastIndexOf` 的 `position` 参数区分。

示例如下：

```TypeScript
'abcdefg'.startsWith('abc'); // true
'abcdefg'.startsWith('bcd'); // false
'abcdefg'.endsWith('efg'); // true
'abcdefg'.endsWith('cde', 5); // true，这里索引 5 对应 f，因此会判断索引 2,3,4 是否正好等于 'cde'
```

# 5.2.10 Unicode 接口

我们不仅可以使用 Unicode 直接编写字符串，还可以使用相应的接口来处理 Unicode 相关的内容。

## Unicode 获取

可以使用 `charCodeAt` 或 `codePointAt` 来获取指定索引的码元对应的 Unicode，它们的类型标注一致：

```TypeScript
function charCodeAt(index?: number): number;
```

`index` 对应的是码元索引，方法会它会返回对应索引码元的 Unicode 值。

示例如下：

```TypeScript
'a'.charCodeAt(0); // 97
'a'.codePointAt(0); // 97
```

这两个方法对于码元数不为 1 的字符处理不同，但是由于极其不常见，所以这里也不再讲解了。

## 根据 Unicode 生成字符

在前面我们讲到可以直接写 `\uxxxx` 或 `\u{}` 来生成对应 Unicode 的字符，但是这种写法不允许传入变量。如果我们需要传入变量，则需要用到 `String.fromCharCode` 或 `String.fromCodePoint` 接口，它们的类型标注一致：

```TypeScript
function fromCharCode(...code: number[]): string;
```

示例如下：

```TypeScript
String.fromCharCode(97, 98, 99); // 'abc'
String.fromCodePoint(97, 98, 99); // 'abc'
```

它们的区别与 `charCodeAt` 和 `codePointAt` 的区别类似，这里也不再讲解。

# 5.2.11 字符串匹配

字符串匹配包括 `match` `matchAll` `search` 三个字符串方法，以及 `RegExp.test` 和 `ResExp.exec` 两个正则表达式方法。

> 学习下面的内容之前必须先学习正则表达式，正则表达式在之前的课程中讲解过：https://h5mota.com/bbs/thread/?tid=1018&p=5#p58，务必看完再来看这一节。

## `RegExpExecArray` 接口

这个接口描述了正则匹配结果数组，它在字符串数组的基础上新增了一些属性。这个接口在后面的讲解中会用到，其部分类型声明如下，先看一眼就行：

```TypeScript
interface RegExpMatchArray extends Array<string> {
    /**
     * 描述了这一匹配项所在的索引
     */
    index?: number;
    /**
     * 被匹配的字符串字面量
     */
    input?: string;
    /**
     * 第一个匹配项，由于没匹配到的时候会返回 null，因此第 0 索引必定是存在的
     */
    0: string;
}
```

## `match` 方法

`match` 方法用于直接匹配正则表达式，其类型声明如下：

```TypeScript
function match(regexp: RegExp): RegExpExecArray | null;
```

当正则表达式不包含 `g` 修饰符时，如果没有搜索到，则会返回 `null`。如果搜索到了，那么返回结果的第 0 索引会是匹配到的字符串内容，后续内容是每一个捕获组（也就是正则表达式圆括号括起来的内容）对应的匹配内容。例如：

```TypeScript
'abc'.match(/\d/); // null，字符串没有数字，匹配不到
'abcdefg,hijklmn'.match(/^(\w+),\w*$/); // ['abcdefg,hijklmn', 'abcdefg']，索引 2 对应捕获组 (\w+)
```

同时这个数组还会包含上面讲到的属性：

```TypeScript
'abcdefg,hijklmn'.match(/^(\w+),\w*$/);
// 数组内容 ['abcdefg,hijklmn', 'abcdefg']
// 对象内容 { index: 0, input: 'abcdefg,hijklmn' }，由于开头就匹配到了，所以 index 是 0。input 就是被匹配的原始字符串
```

当正则表达式包含 `g` 修饰符时，如果没有搜索到，则会返回 `null`。如果搜索到了，那么会返回一个数组，包含每一个匹配项，不会包含捕获组，也不会包含 `index` `input` 这些属性，是一个纯净的数组：

```TypeScript
'abcdefg'.match(/\w/g); // ['a', 'b', 'c', 'd', 'e', 'f', 'g']，纯净的数组，不包含额外属性
```

## `matchAll` 方法

`matchAll` 方法的类型声明如下：

```TypeScript
function matchAll(regexp: RegExp): Iterable<RegExpExecArray>;
```

这个方法要求正则表达式必须包含 `g` 修饰符，如果不包含，则会报错。

匹配结果是一个可迭代对象，这表明你可以通过 `for ... of` 循环或 `[...]` 扩散语法来遍历或转换为数组。匹配结果的每一项都是一个 `RegExpExecArray` 数组，这个数组的第 0 索引表示匹配到的完整字符串，后面的每一项表示每一个捕获组的内容，这与 `match` 不加 `g` 修饰符类似。

举例来说：

```TypeScript
[...'abc,def,ghi,jkl'.matchAll(/(.{2})\w,/g)];
// [
//    ['abc,', 'ab'], { index: 0, input: 'abc,def,ghi,jkl' }
//    ['def,', 'de'], { index: 4, input: 'abc,def,ghi,jkl' }
//    ['ghi,', 'gh'], { index: 8, input: 'abc,def,ghi,jkl' }
// ]
```

这里的结果可能不那么直观，可以好好想一想。

## `search` 方法

`search` 用于搜索第一个在字符串中匹配指定正则表达式的索引，类型声明如下：

```TypeScript
function search(regexp: RegExp): number;
```

对于这个方法来说，正则表达式包含 `g` 修饰符与否不影响结果。返回结果是字符串中第一个匹配成功的索引，举例来说：

```TypeScript
'abc,def'.search(/,.*/); // 4
'abc,def,ghi'.search(/,.*/g); // 4，g 修饰符没有影响
```

## `RegExp.test` 方法

用于判断一个字符串是否符合指定正则表达式的规则，这个是正则表达式对象上的方法，其类型声明如下：

```TypeScript
function test(str: string): boolean;
```

举例来说：

```TypeScript
;/\w+/.test('abcde'); // true，匹配成功，代码前面那个分号是为了让高亮正确，不用管
/\d+/.test('abcde'); // false，匹配失败
```

## `RegExp.exec` 方法

这个方法与 `match` 方法基本一致，但是由于正则表达式的内部状态等原因，并不推荐使用此方法。如果你想判断字符串是否匹配正则表达式，那么应该使用 `test` 方法，如果想匹配字符串内容，应该使用 `String.match` 方法，如果想获取索引，应该使用 `search` 方法。

由于其表现与 `match` 基本一致，这里也不再讲解了。

# 5.2.12 字符串替换

字符串替换会使用到 `replace` 和 `replaceAll` 方法。

## `replace` 方法

类型声明如下：

```TypeScript
function replace(pattern: string | RegExp, replacement: string): string;
function replace(pattern: string | RegExp, replacement: (match: string, ...pn: string[], offset: number, string: number, groups?: { [key: string]: string }) => string): string;
```

这里我们着重讲解第一个方法，第二个方法比较复杂而且使用场景较少，之前简单讲过，这里也不再讲了，如果需要就自己查 mdn 吧。

- `pattern`：表示匹配方式，填字符串的时候表示把原始字符串的第一个 `pattern` 替换，填正则表达式时表示把匹配到的内容替换。如果正则表达式包含 `g` 修饰符，那么会把所有的匹配项都替换。
- `replacement`：替换为的字符串。

`pattern` 填字符串时：

```TypeScript
'Apples are round, and apples are juicy.'.replace('apples', 'oranges');
// Apples are round, and oranges are juicy.
```

`pattern` 填正则表达式时，其基础用法为：

```TypeScript
'Apples are round, and apples are juicy.'.replace(/apples/i, 'oranges'); // i 是大小写不敏感修饰符
// oranges are round, and apples are juicy.
'Apples are round, and apples are juicy.'.replace(/apples/gi, 'oranges');
// oranges are round, and oranges are juicy.
```

替换字符串还可以填写 `$1` 等表示捕获组，填写 `$&` 表示匹配内容等等：

```TypeScript
'Apples are round, and apples are juicy.'.replace(/apples/i, '"$&"');
// "Apples" are round, and apples are juicy.
'Apples are round, and apples are juicy.'.replace(/(apples)/i, '"$1"'); // $1 表示第一个捕获组
// "Apples" are round, and oranges are juicy.
```

`replace` 还有很多用法，具体可以参考这篇 mdn 文档：[String.prototype.replace() - JavaScript | MDN](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Reference/Global_Objects/String/replace)

## `replaceAll` 方法

`replaceAll` 方法一般用于字符串匹配的替换，很少使用正则表达式，因为正则表达式使用 `replace` 也可以实现。`replaceAll` 方法的类型声明与 `replace` 一致，这里也不再列出了。

`pattern` 填字符串时，它会把所有匹配项全部替换，而不是只替换第一个：

```TypeScript
'apples are round, and apples are juicy.'.replaceAll('apples', 'oranges');
// oranges are round, and oranges are juicy.
```

填正则表达式时，要求必须包含 `g` 修饰符，表现与 `replace` 完全一致：

```TypeScript
'Apples are round, and apples are juicy.'.replaceAll(/apples/gi, 'oranges');
// oranges are round, and oranges are juicy.
```
