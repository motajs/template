Phase 9 · 第 66 个计划（增量派发）—— **把 `AudioStreamSource` 的内部换成流式内核，公开面保持不变**。

**要解决的问题（逐条）：**

1. **旧实现先攒后放，不能真正流式播放。** `source.ts` 用 `codec-parser` 解析、`createDecoder` 创建 `ogg-opus-decoder` / `ogg-vorbis`，把所有 PCM 按 10 秒块攒进 `audioData`，再每次 `mergeBuffers()` 重建整个 `AudioBuffer` 并重启 `AudioBufferSourceNode`；缓冲一小段后能播，但每次扩容都重排旧节点，容易在块边界产生断音，且与 09-61..09-65 新建的 mediabunny 会话体系完全脱节。
2. **解码路径重复且互不相通。** 09-65 已经有 `OpusCodecDecoder`、`AudioDecoderRegistry`、7 格式探测与整文件 Vorbis 会话，但流式播放仍走旧解码器，等于同一容器有两套解码实现与两套错误处置。
3. **缺少增量解包。** mediabunny 的 `Input` 只在 `Uint8Array` / `Blob` / URL 上用过，没有验证过 `ReadableStreamSource` 的增量读取，因此需要把 `pump` 的推送式数据转成可拉取流，并在容器判定前缓存足够的头部字节。
4. **调度没有时间线。** 旧 `checkBufferedPlay` 用「已缓冲时长 - 上次开始缓冲点」估算播放位置，暂停续播、循环、`currentTime` 都只是近似，且没有「短窗口提前排期」的概念。

**做法（用户锁定）：**

2. 新增 `pcmScheduler.ts`：`AudioPcmScheduler` 按已解码采样数维护单条源时间线，按窗口提前 `AudioBufferSourceNode.start(when, offset)` 排期；实现暂停 / 续播 / 循环 / 合并 `AudioBuffer`，不使用 `AudioWorklet`。
3. `source.ts` 的 `AudioStreamSource` 改为组合这两个类，保留 `IAudioStreamSource` / `IStreamReader` 的全部公开成员与签名，删除 `codec-parser`、`createDecoder`、`mimeTypeMap`、`isOggPage` 与旧私有解码方法。

## 流式架构（执行依据）

### 1. 数据流

```
StreamLoader.pump(data, done)
  -> AudioStreamSource.pump
     -> AudioStreamDecoder.push(data, done)
        未判定: 追加到 prefix 副本（<= 64 KiB）
        判定 Ogg Opus / WebM Opus:
          StreamBridge.push(prefix + 后续 data)
          Input(ReadableStreamSource) -> EncodedPacketSink.packets()（后台）
            -> OpusCodecDecoder.decode -> 有序队列
        判定 Ogg Vorbis:
          ogg-vorbis.decode(prefix 逐块 + 后续 data)（push 内 await）
            -> 有序队列；done 时 flush
        Unsupported: logger.error(25, hex) + 结束
  <- AudioStreamSource.consumeChunks 后台消费有序队列
     -> AudioPcmScheduler.append(chunk)
        -> 更新 bufferedSamples / sampleRate
        -> 若在播放，立即按窗口排期
     -> maybeStart（阈值满足且未被用户暂停则起播）
StreamLoader.end(true)
  -> AudioStreamSource.end(true)
     -> 等 consumeTask 结束
     -> scheduler.markEnded() + merge() -> buffer
     -> loaded = true + 钩子 onLoad
```

要点：

- **一次消费**：前缀只是 `push` 时的字节副本，判定后 Opus 才写入新建的桥；Vorbis 直接重放前缀给解码库。两者都不会从 `pump` 收到的原始流里二次读取。
- **`pump` 不阻塞**：Opus 只写桥；Vorbis 只 await 当前块的 `decode`（有界）。后台 `packets()` 的阻塞读取发生在 `consumeOpus`，不占用 `pump`。
- **顺序**：`push` 的 await 由 `StreamLoader` 顺序保证；Vorbis 的 `decode` 顺序与字节顺序一致；Opus 的 `packets()` 顺序与容器顺序一致。

### 2. 首包判定（`sniffStreamFormat`）

- `prefix.length < 4`：`NeedMore`。
- 前 4 字节为 `4F 67 67 53`（`OggS`）：需要至少 27 字节；`segments = prefix[26]`；`packetStart = 27 + segments`；再需要 8 字节；若 `prefix[packetStart..packetStart+8]` 为 `OpusHead` 返回 `OggOpus`；若 `prefix[packetStart] === 1` 且随后 6 字节为 `vorbis` 返回 `OggVorbis`；否则 `Unsupported`；不足字节返回 `NeedMore`。
- 前 4 字节为 `1A 45 DF A3`：`WebMOpus`（真正的编码在打开后用 `track.getCodec()` 复核，非 `opus` 即不支持）。
- 其他：`Unsupported`。
- `decideFormat` 的循环上限：`prefixBytes >= SNIFF_LIMIT` 仍为 `NeedMore` 时按 `Unsupported` 处理。

### 3. 推送桥（`StreamBridge`）

- 构造时创建 `readable = new ReadableStream<Uint8Array>({ start: controller => { this.controller = controller; } })`。
- `push(data)`：`closed` 时直接返回；`controller.enqueue(data)`；`size += data.length`。
- `close()`：`closed` 时直接返回；置 `closed`；`controller.close()`。
- 不实现 `cancel` 回调，不向流 `error`；结束只用 `close`，因此 `ReadableStreamSource` 的读取会以 EOF 结束，不会产生未处理拒绝。
- 桥只在 Opus 判定后创建；Vorbis 判定后不创建桥。
- **不做背压判断**：`push` 不读 `controller.desiredSize`，队列随网络到达增长；受 BGM 文件体积与 `ReadableStreamSource` 的 32 MiB 缓存自然限制，且解码后的 PCM 本来就要整曲保留供 `buffer` 与 BGM 缓存池使用，因此不额外丢弃或暂停拉取。

### 4. `AudioStreamDecoder` 状态机

- 字段：`info`、`failed`、`ended`、`prefix`、`prefixBytes`、`format`、`bridge`、`input`、`opusDecoder`、`vorbis`、`opusTask`、`pending`、`waiter`、`vorbisSamples`、`headerHex`、`errorReported`。
- `push(data, done)`：
  1. `failed` / `ended` 时直接返回。
  2. **终止推送优先**：`data === undefined` 时——未判定且 `done` 为真：`fail(25)` 并返回（不追加前缀、不判定、不解码）；未判定且 `done` 为假：直接返回；已判定 Opus：`bridge?.close()` 并返回；已判定 Vorbis：`await runVorbisChunk(null)` 并返回。**任何路径都不得把 `undefined` 追加到 `prefix` / `pending`，也不得传给 `decode`。**
  3. 未判定且有数据：追加到 `prefix` 并累计字节；用拼接后的前缀调用 `sniffStreamFormat`；`NeedMore` 且未 `done` 且未超过上限时返回（不阻塞）。
  4. `Unsupported`：`fail(25)` 并返回。
  5. 判定成功：记下 `headerHex` 与 `format`。Opus：调用**同步**的 `prepareOpus(guess)`（建桥、把前缀写入桥、清空前缀），随后 `void this.openOpus(guess).catch(() => { if (!this.ended && !this.failed) this.fail(97); })` 起后台任务（`close()` / `free()` 中止时不记错误码）；**不得在 `push` 内 await `openOpus`**，否则 `canRead()` 等待后续字节时无人再 `push`，形成死锁。Vorbis：`await openVorbis()`（只解码已收到的前缀，不需要后续字节，有界）。
  6. 判定发生的这一次 `push` 的 `data` 已随前缀被对应路径消费，不再单独处理；若 `done` 为真，按第 2 条收尾。
  7. 已判定后的后续 `push`：Opus `bridge.push(data)`；Vorbis `await runVorbisChunk(data)`；`done` 时按第 2 条收尾。
- `prepareOpus(guess)`：`this.format = guess`；`this.bridge = new StreamBridge()`；把 `prefix` 按原顺序 `push` 进桥；清空前缀与 `prefixBytes`。
- `openOpus(guess)`（后台，`void` 启动）：
  1. 从已建好的桥创建 `new Input({ formats: [guess === OggOpus ? OGG : WEBM], source: new ReadableStreamSource(bridge.readable) })`。
  2. `canRead()` 失败、无主音轨、`getDecoderConfig()` 无 `Uint8Array` 描述、`parseOpusIdentificationHeader` 失败：`fail(97)`。
  3. `track.getCodec()` 非 `'opus'`：`fail(25)`。
  4. `opusDecoder` 为空：`fail(97)`；否则 `configure(info, description)`；`info = { container: Ogg | WebM, codec: Opus, sampleRate: 48000, channels: header.channels, duration: null }`。
  5. `this.opusTask = this.consumeOpus(track).catch(() => { if (!this.ended && !this.failed) this.fail(25); })`（挂后台，不 await；`.catch` 是 Promise 处理器，不是 `try` / `catch` 语法）。`openOpus` 自身抛出的拒绝由调用点的 `.catch` 转 `fail(97)`；每个 `await` 之后若 `failed` 或 `ended` 已为真，先 `this.input?.dispose(); this.input = null;` 再返回，不再启动后续步骤。
- `consumeOpus(track)`：`for await (const packet of new EncodedPacketSink(track).packets())`；每次迭代先判断 `if (this.ended || this.failed) break;`；每次 `decoder.decode(packet.data, packet.timestamp, packet.duration)`，非空则 `enqueue`；循环结束后 `wake()` 并把 `ended` 置真；循环结束（正常完成或提前 break）后统一 `this.input?.dispose()`、`input = null`。任何迭代或解码拒绝都由调用点的 `.catch`（带 `!ended && !failed` 守卫）收口，`fail` 会置 `ended` 并 `wake()`，保证 `consumeTask` 一定终止。
- `openVorbis()`：`this.format = StreamFormatGuess.OggVorbis`；`const decoder = await loadVorbisStreamDecoder().catch(() => { if (!this.ended && !this.failed) this.fail(97); return null; })`；`decoder` 为空直接返回；成功后把 `prefix` 逐块 `await runVorbisChunk(part)`；清空前缀与 `prefixBytes`。
- `runVorbisChunk(data)`：**唯一一处** `try` / `catch`，同时覆盖 `decode` 与 `flush`：`try { decoded = data ? await vorbis.decode(data) : await vorbis.flush(); } catch { void vorbis?.free(); vorbis = null; this.fail(25); return; }`；`enqueueVorbis(decoded)`；`data` 为 `null` 时再 `ended = true`、`wake()`、`void vorbis.free()`、`vorbis = null`。不得拆成两个 `try` 块。
- `enqueueVorbis(decoded)`：`decoded.samplesDecoded === 0` 时直接返回；若 `info` 为空则用首块建立 `info`（`container: Ogg`、`codec: Vorbis`、`sampleRate`、`channels`、`duration: null`）；`timestamp = this.vorbisSamples / sampleRate`；`channelData` 逐声道复制为新的 `Float32Array`；`vorbisSamples += samplesDecoded`。
- `generateChunks()`：无限循环；`pending` 非空时用 `splice(0, 1)` 取块后 `yield`（避免 `shift()` 的 `undefined` 类型）；否则 `ended` 为真则 `return`；否则 `await new Promise(resolve => { waiter = resolve; })` 后继续。
- `enqueue(chunk)`：`errors` 非空且尚未记录时记一次 `logger.error(25, headerHex)`（`errorReported` 私有布尔）；`pending.push(chunk)`；`wake()`。
- `close()`：`ended = true`；`bridge?.close()`；`void vorbis?.free()`；`vorbis = null`；`wake()`；不在此处 `dispose()` 输入（等 `consumeOpus` 自然结束）。
- `fail(code)`：`failed` 已真则返回；置 `failed` / `ended`；`logger.error(code, headerHex)`；`bridge?.close()`；`void vorbis?.free()`；`vorbis = null`；`this.input?.dispose(); this.input = null;`（`fail` 只会在 `consumeOpus` 启动之前或 Vorbis 路径被调用，此时无消费者在读输入）；`wake()`。

### 5. `AudioPcmScheduler` 算法

- `append(chunk)`：
  1. `chunk.sampleRate` 为 0 或 `chunk.samplesDecoded` 为 0：直接返回。
  2. 首个有效块写入 `sampleRate` / `channelCount`；后续块声道数不一致则丢弃该块（静默）。
  3. 记录 `chunkStarts.push(bufferedSamples)`；`chunks.push(chunk)`；`bufferedSamples += chunk.samplesDecoded`。
  4. `windowDuration` 对应的 `maxWindowSamples = max(1, floor(windowDuration * sampleRate))`。
  5. 若 `playing`：仅当采样率此前未知（`sampleRate` 刚由本块写入）时才用 `pendingStart` 建立锚点，建立后立刻 `pendingStart = 0`；采样率早已已知时不得读取 `pendingStart`，直接 `schedule()`。
- `start(when)`：`playing` 为真直接返回；否则先 `playing = true`（**不得清 `ended`**：`ended` 只由 `markEnded()` 置真，仅由 `free()` 复位，保留 `loop`）；`sampleRate === 0` 时 `pendingStart = when` 并返回；否则以**传入的 `when`** 建立锚点（`anchorSample = min(when, duration)`、`anchorTime = ac.currentTime`、`scheduledSamples = floor(anchorSample * sampleRate)`、`pendingOffset = anchorSample * sampleRate - scheduledSamples`、`plannedTime = anchorTime`）并 `schedule()`。不得在该分支使用 `pendingStart`。（`AudioStreamSource` 的 `maybeStart` 已保证 `sampleRate > 0`，该 `sampleRate === 0` 分支不会被正常播放路径触发，仅作直接复用调度器时的保底，不影响正常流程。）
- `schedule()`：`while (scheduledSamples < bufferedSamples)`：
  1. `const start = scheduledSamples;`
  2. `const end = min(bufferedSamples, start + maxWindowSamples);`
  3. `const when = max(ac.currentTime + MIN_START_LEAD, plannedTime);`
  4. `const offset = pendingOffset;`
  5. 若 `when + (end - start - offset) / sampleRate <= ac.currentTime`：整窗已过期，`scheduledSamples = end`、`pendingOffset = 0`，继续。
  6. 否则 `const node = ac.createBufferSource(); node.buffer = buildWindow(start, end); node.connect(target.input); node.onended = () => this.handleNodeEnd(node); node.start(when, offset / sampleRate);`；`plannedTime = when + (end - start - offset) / sampleRate`；`scheduledSamples = end`；`pendingOffset = 0`；`nodes.add(node)`；`lastNode = node`。
- `buildWindow(start, end)`：用 `ac.createBuffer(channelCount, end - start, sampleRate)`；逐声道从重叠的 `chunks` 片段 `set` 进临时数组后 `copyToChannel`。
- `handleNodeEnd(node)`：`nodes.delete(node)`；**若 `!this.playing` 直接返回**（暂停 / 释放导致的 `ended` 不得重排或回调）；**若 `nodes.size > 0` 直接返回**；若 `scheduledSamples < bufferedSamples` 直接返回（仍在缓冲，保持 `playing`）；若 `ended` 且 `loop`：`restartLoop()`；否则若 `ended`：`playing = false`、`haltedTime = duration`、`onPlaybackEnd()`；未结束则保持 `playing` 等新数据。`schedule()` 一次排完全部可用窗口，存活节点集合与 `playing` 共同决定是否最后结束。
- `restartLoop()`：先对所有存活节点置 `node.onended = null` 再 `stop()`，并清空 `nodes`（触发重排的节点已在 `handleNodeEnd` 中移除）；随后 `anchorSample = 0`、`anchorTime = max(plannedTime, ac.currentTime)`、`scheduledSamples = 0`、`pendingOffset = 0`、`plannedTime = anchorTime`，再 `schedule()`。
- `stop()`：先 `haltedTime = currentTime`、`playing = false`；随后 `nodes.forEach(node => { node.onended = null; node.stop(); })`、`nodes.clear()`；返回 `haltedTime`。先摘除 `onended` 是为了避免 `node.stop()` 异步触发的 `ended` 再进入 `handleNodeEnd`。
- `currentTime`：`playing` 时取 `min(anchorSample + (ac.currentTime - anchorTime), scheduledSamples / sampleRate)`，再夹到 `[0, duration]`；非播放时取 `haltedTime`。
- `merge()`：`bufferedSamples === 0` 返回 `null`；否则 `ac.createBuffer(channelCount, bufferedSamples, sampleRate)`，逐声道用 `buildWindow(0, bufferedSamples)` 的通道数据 `copyToChannel`。
- `free()`：`stop()`；清空 `chunks` / `chunkStarts` / `nodes` / 计数与锚点；`sampleRate = 0`、`bufferedSamples = 0`、`channelCount = 0`、`haltedTime = 0`、`pendingStart = 0`、`playing = false`、`ended = false`（保留 `loop`，复用的调度器不携带旧的结束状态）；`lastNode = idleNode`。

### 6. `AudioStreamSource` 组装

- 构造器：`this.ac = motaAC.ac`；`this.scheduler = new AudioPcmScheduler(this.ac, () => this.handlePlaybackEnd())`；不再创建 `output` 字段（改为 `get output() { return this.scheduler.output; }`）。
- `start()`（流开始）：`teardownDecoder()`；`this.scheduler.free()`（重置旧时间线、PCM 与 `ended`，保留 `loop`，保证复用的源不会以 `ended === true` 起播）；清空公开计数与 `buffer`；`stoppedByUser = false`；`errored = false`；`this.decoder = new AudioStreamDecoder(this.motaAC.createCodecDecoder(AudioCodec.Opus))`；`this.consumeTask = this.consumeChunks()`。
- `pump(data, done)`：`if (this.errored) return;`；`const decoder = this.decoder; if (!decoder) return;`；`await decoder.push(data, done);`；`if (decoder.failed) this.errored = true;`；`maybeStart();`。不再 reject、不再解析头；终止用的 `pump(undefined, true)` 原样交给解码器处理。
- `consumeChunks()`：`const decoder = this.decoder!; for await (const chunk of decoder.chunks) { if (this.decoder !== decoder) return; this.appendChunk(chunk); }`；循环结束后 `if (decoder.failed) this.errored = true;`（终止推送后才暴露的失败也要置真）；该守卫保证 `free()` 已把 `decoder` 置空后，正在等待的迭代不会再向已清空的调度器追加数据。
- `appendChunk(chunk)`：`if (this.errored || chunk.samplesDecoded === 0 || chunk.sampleRate === 0) return;`；`if (this.sampleRate === 0) this.sampleRate = chunk.sampleRate; else if (this.sampleRate !== chunk.sampleRate) logger.warn(48);`；`this.scheduler.append(chunk)`；`this.bufferedSamples = this.scheduler.bufferedSamples`；`this.buffered = this.scheduler.duration`；`this.maybeStart()`。
- `maybeStart()`：`if (this.playing || this.errored || this.stoppedByUser) return;`；`if (this.sampleRate === 0) return;`；`if (!this.loaded && this.buffered < this.bufferPlayDuration) return;`；`this.scheduler.start(0)`；`this.playing = true`；`this.forEachHook(hook => hook.onPlay?.());`。
- `play(when)`：`if (this.playing || this.errored) return;`；`this.stoppedByUser = false;`；`if (this.sampleRate > 0 && (this.loaded || (when ?? 0) <= this.buffered)) { this.scheduler.start(when ?? 0); this.playing = true; this.forEachHook(hook => hook.onPlay?.()); } else { this.controller?.start(); }`。
- `stop()`：`const time = this.scheduler.stop(); this.playing = false; this.stoppedByUser = true; return time;`。
- `end(done, reason)`：`if (!done) { logger.warn(44, reason ?? ''); this.teardownDecoder(); return; }`；`this.controller = null; void this.finishLoad();`。
- `finishLoad()`：`const task = this.consumeTask; if (task) await task;`；`this.scheduler.markEnded()`；`this.buffer = this.scheduler.merge();`；`this.buffered = this.scheduler.duration; this.duration = this.scheduler.duration;`；`this.loaded = true;`；`this.maybeStart();`；`this.forEachHook(hook => hook.onLoad?.());`；`this.teardownDecoder()`（保留 `buffer` 与调度器数据供播放）。
- `currentTime`：显式 `get currentTime(): number { return this.scheduler.currentTime; }`；删除旧 `lastStartWhen` / `lastStartTime` / `lastBufferSamples` 推导后，这里必须是唯一的位置来源。
- `handlePlaybackEnd()`：`this.playing = false; this.forEachHook(hook => hook.onEnd?.());`。
- `teardownDecoder()`：`const decoder = this.decoder; this.decoder = null; if (!decoder) return; decoder.close();`。
- `free()`：`this.stop()`；`this.scheduler.free()`；`this.teardownDecoder()`；`this.consumeTask = null`；重置 `buffer` / `loaded` / `buffered` / `bufferedSamples` / `sampleRate` / `duration` / `errored` / `stoppedByUser`。
- `setLoop(loop)`：`this.scheduler.setLoop(loop);`（`loop` 状态只由调度器持有）。
- `connect(target)`：`this.scheduler.connect(target);`。
- `setChunkSize(size)`：`if (this.controller?.loading || this.loaded) return; this.scheduler.setWindowDuration(size);`。
