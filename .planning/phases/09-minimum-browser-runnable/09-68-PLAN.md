Phase 9 · 第 68 个计划（增量派发）—— **让 BGM 接上新的流式内核，并补上 WebM 类型**。

**要解决的问题（逐条）：**

1. **`.webm` 的 BGM 现在直接被拒。** `support.ts` 的 `typeMap` 只有 `ogg` / `mp3` / `wav` / `flac` / `opus` / `aac` 六项，`AudioType` 也没有 WebM 成员，因此 `guessTypeByExt('xxx.webm')` 返回空串，`bgm.ts` 走 `logger.warn(50)` 后直接返回，WebM 格式的 BGM 根本加不进来。
2. **BGM 仍按旧假设选源。** `bgm.ts` 目前是「`isAudioSupport(type)` 为真用 `<audio>`，否则一律用 `AudioStreamSource` + `StreamLoader`」。这个「否则」在 09-61..09-67 之后已经错了：新的 `AudioStreamDecoder` 只认 Ogg Opus、Ogg Vorbis 与 WebM Opus，MP3 / WAV / FLAC / AAC 一旦落在流式分支里只会被判不支持并停止，播放彻底失效。
3. **选择依据缺一条。** 正确条件有两个且互相独立：浏览器能不能原生播（`isAudioSupport`）、新流式内核能不能解码（本次新增的格式判定）。只有「原生不支持 且 可流式」才该走 `AudioStreamSource`。
4. **没有 Node 侧防线。** 扩展名映射与选择矩阵目前没有任何自动化覆盖，只能靠人工在浏览器里试；`support.ts` 在模块作用域 `new Audio()`，Node 下直接 import 会抛 `Audio is not defined`，所以需要先立一个全局桩再动态导入。

```ts
addBGMFromURL(id: T, url: string) {
    const type = guessTypeByExt(id);
    if (!type) {
        logger.warn(50, id.split('.').slice(0, -1).join('.'));
        return;
    }
    const gain = this.ac.createVolumeEffect();
    // 流式音频源只支持 Ogg 与 WebM 的 Opus / Vorbis，其余格式必须交给 audio 元素
    const useElement = isAudioSupport(type) || !isAudioStreamSupport(type);
    if (useElement) {
        const source = this.ac.createElementSource();
        source.setSource(url);
        source.setLoop(true);
        const route = this.ac.createRoute(source);
        route.addEffect([gain, this.mainGain]);
        this.ac.addRoute(this.getId(id), route);
        this.setTransition(id, route, gain);
    } else {
        const source = this.ac.createStreamSource();
        const stream = new StreamLoader(url);
        stream.pipe(source);
        source.setLoop(true);
        const route = this.ac.createRoute(source);
        route.addEffect([gain, this.mainGain]);
        this.ac.addRoute(this.getId(id), route);
        this.setTransition(id, route, gain);
    }
}
```

约束：两个分支体内的语句（含顺序与参数）逐字沿用现场代码，只把 `if (isAudioSupport(type))` 换成上面两行；`import` 行改为按 prettier 结果展开的三名导入；类中其它方法逐字不动。
