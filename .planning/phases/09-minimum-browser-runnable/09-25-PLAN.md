Phase 9 · 第 25 个计划（新增的独立增量，**不是** 09-01..09-24 的 UI 迁移任务）—— **修正地图渲染的半透明图块排序缺陷（两遍式渲染 + 覆盖层），并修好后处理 FBO 的深度附件与 ping/pong 配对**。

**要解决的问题：** 地图渲染目前是「绘制顺序 + 深度缓冲兜底」的混合方案：`gl.enable(DEPTH_TEST)`、`depthFunc(LESS)`、深度写入保持默认 `true`、alpha 混合开启（`renderer.ts` 规划日实测约 788–796 行）；绘制顺序是实例缓冲区的自然顺序（`[chunk][layer][row][col]`，见 `MapVertexBlock.rebuild`），动态块追加在静态数组末尾并最后绘制（`vertex.ts` 的 malloc 与 `viewport.ts` 的 `checkDynamic`）。这对不透明图块可以接受，但对半透明图块是错的：半透明面要么把后提交的更远表面挖掉（洞），要么以错误顺序混合。

**做法（锁定设计）：**
- **两遍式**：不透明遍保持现有分块批量实例化绘制与 `depthMask(true)`，分块张量不重排；透明覆盖层最后绘制，`depthMask(false)`、深度测试仍开、混合开。覆盖层含「有效 alpha `< 1` 的静态图块」+「全部动态块」，按 `(layerIndex, y, x, kind)` 后到前排序；x 只做 CPU 侧稳定次级键，绝不进深度。**条目身份唯一**：静态键 = 种类 + 层索引 + 地图 x + 地图 y，动态键 = 种类 + 移动索引；同一格在不同图层的半透明图块因此是两条独立条目。
- **静态提取**：alpha 跨到 `< 1` 时把该实例 `x/y/w/h` 置 0（复用空图块机制）并登记覆盖层记录（rect 等）；回到 1 时写回并注销；不压缩、不重排分块数组。
- **覆盖层存储**：独立的小型暂存实例数组 + 独立 GPU 缓冲区，按缓存顺序组装后用 `drawArraysInstanced` 绘制；不重排动态数组，保留 `MovingBlock.index` 身份。
- **脏标记**：值脏（alpha / frame / 纹理等不改排序键的值）只重传不重排；顺序脏（成员变化、跨阈值、动态增删 / 移动、重建、图层变化）才重排；排序在 `render()` 内惰性执行；任一脏都让 `needUpdate()` 为真。动态条目的 `layerIndex` 在组装时按当前图层顺序重新推导，图层列表 / zIndex 变化不会留下旧排序键。
- **状态卫生**：显式 `depthMask(true)` / `depthMask(false)` 与收尾恢复；混合改 `blendFuncSeparate`；`map.frag` 的 discard 阈值 `0.1` → `0.004`。
