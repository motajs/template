<objective>
Phase 9 · 第 33 个计划（新增的独立增量）——**把 `packages-user/client-base/src/setting/types.ts` 的两个空壳 interface 替换为用户已批准的 6 个类型声明（纯类型层，零实现）**。

**要解决的问题：**

`setting/types.ts` 现在只有 `export interface ISettingItem {}` 与 `export interface ISettingSystem {}` 两个空接口，`setting/index.ts` 也已经 `export * from './types';`，但接口内部没有任何成员。后续所有设置相关工作（设置系统实现、设置项工厂、设置界面、存档注册）都需要一个确定的数据契约，否则每个后续计划都要先自行发明一套字段，导致实现层漂移。本计划先把契约钉死。

**做法（用户已批准的声明草案，不得扩大）：**

1. `ISettingItem<T = unknown> extends ISaveableContent<T>`：`id` / `name` / `description` 三个只读字段 + `getValue` / `setValue` / `getPreviewString` / `getSettingComponent` 四个方法。存档 / 读取完全继承 `ISaveableContent<T>`，不在本接口重复声明。
