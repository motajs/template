## v2 二进制布局（解析器的唯一字节依据）

| 偏移 | 长度 | 字段 | 说明 |
|------|------|------|------|
| 0 | 4 | signature | ASCII `ANIM`；按大端 UInt32 读为 `0x414E494D` |
| 4 | 4 | version | UInt32LE，必须为 `2` |
| 8 | 4 | imageDataSize | UInt32LE，图像段总字节数（含 sprite 表与 WebP） |
| 12 | 4 | metaDataSize | UInt32LE，元数据 JSON 字节数 |
| 16 | 4 | spriteCount | UInt32LE，必须 ≥ 1 |
| 20 | spriteCount × 8 | sprite dimensions | 每个 sprite 依次 `width` / `height`，各 UInt32LE，必须 ≥ 1 |
| `20 + spriteCount * 8` | `imageDataSize - 4 - spriteCount * 8` | WebP | 单个 WebP 图像块，长度必须 ≥ 1 |
| `16 + imageDataSize` | `metaDataSize` | metadata | UTF-8 JSON，长度必须 ≥ 1 |

**总长度恒等式：** `buffer.byteLength === 16 + imageDataSize + metaDataSize`；不满足即拒绝。头部固定 16 字节；`imageDataSize` 覆盖从偏移 16 开始的整段图像数据（含 4 字节 spriteCount 与 sprite 尺寸表）。

**sprite 尺寸表的用途与已知限制：** sprite 宽高在读表时校验为 `>= 1`，sprite 数量用于计算 WebP 起始偏移；除此之外不与元数据 `bitmaps` 或解码后的 `image.width` / `image.height` 交叉比对。现有格式未给出「sprite 表尺寸必须等于 bitmap 尺寸或解码图尺寸之和」的依据，推测性拒绝可能误杀合法文件，因此裁剪矩形一律以元数据 `bitmaps` 为准。该限制必须由 Task 5 的 SUMMARY 如实记录。

```ts
    blend: number; // 0 = normal, 1 = add
    bitmaps: IRawAnimationBitmap[];
    frame: IRawAnimationFrame[];
}
```

`ratio` 为动画整体缩放系数；`blend` 映射到 `AnimationBlendMode.Normal` / `AnimationBlendMode.Add`。`objects` 元组固定 5–7 个元素：前 5 个必填，`mirror` / `rotate` 可选，缺省为 0；`bitmaps` 一律使用 `IRawAnimationBitmap`，`sound` 一律使用 `IRawAnimationSound`，文件中不得出现内联重复的对象类型。

## 解析器设计（`parse.ts`）

**公开入口：** `export async function parseRenderAnimation(buffer: ArrayBuffer): Promise<IAnimationParsedData>`。

**解析与校验顺序（先纯字节/JSON 校验，再解码图像，避免解码后才发现结构错误）：**

1. `new DataView(buffer)`；读头部：签名、版本、`imageDataSize`、`metaDataSize`；执行总长度恒等式与最小长度校验。
2. 读 `spriteCount` 与每个 sprite 的宽高；要求 `spriteCount >= 1`、`4 + spriteCount * 8 < imageDataSize`、每个宽高 `>= 1`。
3. 切出 WebP 字节（`webpOffset = 20 + spriteCount * 8`、`webpSize = imageDataSize - 4 - spriteCount * 8`）与元数据字节（`metaOffset = 16 + imageDataSize`）。
4. `new TextDecoder('utf-8').decode(metaBytes)` 后 `JSON.parse`；**不写 `try-catch`**，JSON 语法错误由 `JSON.parse` 直接抛出。
5. 校验 raw 元数据：`ratio` 有限且 `> 0`；`blend` 为 `0` 或 `1`；`bitmaps` 为数组且长度等于 `spriteCount`；每个 bitmap 的 `x/y` 有限且 `>= 0`、`width/height` 有限且 `>= 1`；`frame` 为数组；每帧 `objects` 若存在则为数组，每个元组长度 5–7，`index` 为整数且在 `[0, bitmaps.length)`，`x/y/scale/opacity/rotate` 有限，`scale > 0`，`opacity` 在 `[0, 255]`，`mirror` 为有限数字（缺省 0；非 0 即镜像），`rotate` 缺省 0；每帧 `sound` 若存在则为数组，`name` 为非空字符串，`volume` / `pitch` 若存在则有限。
6. `await createImageBitmap(new Blob([webpBytes], { type: 'image/webp' }))` 得到 `ImageBitmap`。
7. 用解码后的 `image.width` / `image.height` 校验每个 bitmap 在纹理范围内：`x >= 0`、`y >= 0`、`width >= 1`、`height >= 1`、`x + width <= image.width`、`y + height <= image.height`；失败时先 `image.close()` 再抛出，避免泄漏。
8. `const texture = new Texture(image)`。
9. 逐帧转换：`objects` 用 `toObject`（`scale = rawScale * ratio`，`mirror` / `rotate` 缺省 0）；用 `computeFrameBox` 计算 `width/height/originX/originY`；`sound` 原样保留可选字段。
10. 返回 `{ texture, bitmaps, frames, blend }`；`bitmaps` 使用 raw 元数据中的 `x/y/width/height`，不按 ratio 改尺寸（它们是纹理源裁剪矩形）。

**错误策略：** 所有校验失败抛出 `Error`，消息为明确中文（例如签名无效、版本不支持、长度不符、sprite 数量无效、位图越界、帧对象索引越界、混合模式无效）；不写 `try-catch`，不吞掉 `JSON.parse` / `createImageBitmap` 的错误。

**浏览器 API 约束：** `DataView` / `Uint8Array` / `TextDecoder` / `Blob` / `createImageBitmap` / `Texture`；生产代码不引入 Node 内置模块、原生图像库或文件系统 API。

## 帧包围盒 / 原点公式（解析器与动画器共用）

**记号：** 对帧内每个对象 `i`：

- `eff_i = rawScale_i * ratio`（解析器存入 `IAnimationObject.scale` 的有效百分数）
- `w_i = bitmap.width * eff_i / 100`
- `h_i = bitmap.height * eff_i / 100`
- `a_i = rotate_i * PI / 180`
- `hx_i = (w_i / 2) * |cos(a_i)| + (h_i / 2) * |sin(a_i)|`
- `hy_i = (w_i / 2) * |sin(a_i)| + (h_i / 2) * |cos(a_i)|`
- `left_i = x_i - hx_i`、`right_i = x_i + hx_i`
- `top_i = y_i - hy_i`、`bottom_i = y_i + hy_i`

**并集（无对象时全部取 0）：**

- `minX = min(left_i)`、`maxX = max(right_i)`
- `minY = min(top_i)`、`maxY = max(bottom_i)`

**帧尺寸与原点：**

- `width = max(1, ceil(maxX - minX))`
- `height = max(1, ceil(maxY - minY))`
- `originX = -minX`（动画中心在帧画布内的横坐标）
- `originY = -minY`

**镜像：** `mirror` 只影响绘制方向；矩形以对象中心为轴翻转后，轴对齐包围盒不变，因此不进入 `hx_i` / `hy_i` 公式。

**绘制位置（动画器）：** 对象中心在帧画布内为 `(originX + x_i, originY + y_i)`；先 `translate` 到该点，再按旧顺序 `scale(-1, 1)`（mirror）→ `rotate(-rotate_i * PI / 180)` → `drawImage(source, bitmap.x, bitmap.y, bitmap.width, bitmap.height, -w_i/2, -h_i/2, w_i, h_i)`。

**算例 1（无旋转）：** 单个 32×32 bitmap，`ratio = 1`、`rawScale = 100`、`x = y = 0`、`rotate = 0`。`eff = 100`、`w = h = 32`、`hx = hy = 16`；`minX = -16`、`maxX = 16`、`minY = -16`、`maxY = 16`；`width = height = 32`、`originX = originY = 16`；绘制中心 `(16, 16)`，左上角 `(0, 0)`。

**算例 2（45° 旋转）：** 同上但 `rotate = 45`。`hx = hy = 16 * 0.7071 + 16 * 0.7071 ≈ 22.627`；`width = height = ceil(45.254) = 46`；`originX = originY ≈ 22.627`。

**算例 3（空帧）：** `objects` 为空；`minX = maxX = minY = maxY = 0`；`width = height = 1`、`originX = originY = 0`；动画器返回透明 1x1。

## 动画器设计（`animater.ts`）

- `export class RenderAnimater implements ITextureAnimater<IAnimationParsedData>`。
- `once(texture, data)` / `cycled(texture, data)` 返回 `Generator<ITextureRenderable, void>`；二者委托私有生成器 `sequence(texture, data, cycled)`，`once` 走一遍，`cycled` 回到第 0 帧无限循环。
- `sequence` 在 `data.frames.length === 0` 时直接 `return`（不 yield）。
- 每帧调用私有 `composeFrame(texture, data, frame)`：
  - `const canvas = new MotaOffscreenCanvas2D();`
  - `canvas.setHD(false);`
  - `canvas.setAntiAliasing(false);`
  - `canvas.size(frame.width, frame.height);`（`size` 会 clamp 到至少 1×1）
  - 遍历 `frame.objects`，按上文公式绘制；每个对象 `ctx.save()` / `ctx.restore()`，`ctx.globalAlpha = object.opacity / 255`。
  - 返回 `canvas`。
- yield `{ source: canvas.canvas, rect: { x: 0, y: 0, w: frame.width, h: frame.height } }`；`source` 必须是 `HTMLCanvasElement`（`canvas.canvas`），不能是 `MotaOffscreenCanvas2D` 包装对象。
- **清理策略（用户决定 1B，不使用 `try/finally`）：** `sequence` 用局部变量保留上一帧画布引用；每次 `.next()` 从 yield 恢复后、合成新帧之前，先对上一帧执行 `canvas.clear()` 并把 `canvas.canvas.width` / `canvas.canvas.height` 设为 `0` 释放后备存储。`once` 走完最后一帧、生成器正常结束时，释放最后一帧画布。提前调用 `.return()` 会跳过正常结束路径，最后一帧画布不做清理、交给 GC；这是有意的取舍，SUMMARY 必须如实记录，本计划不承诺 `.return()` 清理。
- 空帧没有对象，`composeFrame` 仍创建 1×1 画布，不调用 `drawImage`，yield 透明 1×1。
- 不实现帧计时 / 循环定时 / 请求动画帧；`once` / `cycled` 只控制帧序列。
- 不调用 `texture.dispose()` / `data.texture.dispose()`；源纹理由调用方拥有。
