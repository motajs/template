**本计划是代码改动计划**（不同于 04-01 / 04-02 的只读清点）：改动面严格限定为三个文件 —— `render/map/extension/hero.ts`（勇士渲染拓展本体）、`.../extension/types.ts`（拓展契约）、`.../extension/manager.ts`（拓展管理器）。三者构成 `IMapExtensionManager.addHero → MapHeroRenderer(hero: IHeroLocation) → hero.addHook / hero.mover.addHook → 钩子回调驱动渲染` 这一条最小闭环。

**要解决的问题（三条，全部来自 04-02 对账的「渲染端需改」）：**
1. **类型名整体失配**（`#04-02-R-03/R-04/R-12`）：渲染端 import 的 `HeroAnimateDirection`、`IHeroMoveController`、`IHeroMoveControllerHooks` 在数据端**不存在**（当前靠 `// @ts-expect-error 需要重构` 压着）；`heroMap` / `addHero` / `removeHero` 的键类型是已消失的控制器。
2. **成员形状失配**（`#04-02-R-05/R-06`）：`hero.direction` 在现行接口不存在（朝向为 `faceDirection` / `moveDirection` / `getCurrentFaceDirection()`）；`hero.image` 无数据端对位（D-18 待用户处理）。
3. **钩子族整体断链**（`#04-02-R-01` 与缺失候选 `#04-02-G-01`）：渲染端 `MapHeroHook` 实现的 `onSetPosition` / `onStartMove` / `onMoveHero` / `onEndMove` / `onJumpHero` / `onTurnHero` 在数据端没有同名对位，须改接现有钩子（D-21 裁决：不新增数据端接口）。

**大致解决方案：**
- **绑定对象换成位置对象**：`MapHeroRenderer` 持有 `IHeroLocation`；坐标读 `IObjectMovable.x/.y`；朝向读 `getCurrentFaceDirection()`（构造期初始化）与 `mover.faceDirection`；移动方向读 `mover.moveDirection`；动画播放方向读 `mover.currAnimDir` 并改用 `ObjectAnimDirection`（R-03/R-05/R-06）。
- **钩子改为订阅现有钩子**（D-21）：在 `hero`（`IHeroLocationHooks`）与 `hero.mover`（`IObjectMoverHooks<IHeroLocation>`）上各注册一次 `MapHeroHook`，用 `load()` / `unload()` 管理（原 `controller` 字段拆为两个控制器字段）。渲染端实现现有钩子成员名，旧名全部删除；`onStepEnd` 成为逐格渲染的驱动点（此时 `tile` 坐标已更新），按 `ObjectMoveType` 分派到既有渲染内部方法。
- **被动化**（D-20）：`IMapHeroRenderer` 去掉「外部驱动渲染状态」的成员（`startMove` / `waitMoveEnd` / `stopMove` / `move` / `jumpTo` / `setPosition` / `turn` / `setHeroAnimateDirection`；其中 `setHeroAnimateDirection` 的**接口声明**因形参类型 `HeroAnimateDirection` 在数据端已不存在，在 Task 1 随类型改名一并删除（`MapHeroRenderer` 上的类内实现方法保留），其余 7 个的接口声明在 Task 2 删除）；这些方法退为渲染端内部实现，仅由钩子回调调用。
- **范围硬边界**：贴图 / 不透明度（D-18）、跟随者（D-22）、`action/move.ts` 与移动控制（D-19）、`core.*`（D-12）、裸函数（D-11）一律不动。
