**源码事实（写作时以此为准）：**
- `IEnemyAttr` 在 `packages-user/data-common/src/types.ts`，当前含 `name` / `hp` / `atk` / `def` / `money` / `exp` / `point` / `guard`；`guard` 是支援来源的集合，不是内容文件里的普通数值。
- 怪物模板是 `IEnemyRawData`（`num` + `attribute` + `special`）；默认模板在 `src/content/defaults/enemy.jsonc`，实际内容在 `src/content/enemy.jsonc`。
- `Enemy` 的 `getAttribute` / `setAttribute` / `addAttribute`；`IReadonlyEnemy` 只暴露 `getAttribute` 与 `cloneAttributes`。
- `EnemyContext.buildup()` 的顺序是：视图 `reset` → `buildupSpecials`（全局光环 + 特殊属性转光环 + 按优先级处理特殊查询）→ `buildupBase`（按优先级从高到低执行基础光环）→ `buildupQuery`（常规查询）→ `buildupFinal`（最终效果）；结束后把伤害系统与地图伤害全部标脏。
- 优先级：数值越大越先执行；特殊属性产生的光环不能反向影响当前或更高的优先级；局部刷新 `refreshEnemy` 只重算命中该怪物的光环与查询。
- 脏标记：`markDirty(view)` 把视图加入 `dirtyEnemy` 并同步伤害系统；`requestRefresh(view)` 决定全量 `buildup` 还是局部 `refreshEnemy`；`needTotallyRefresh` 表示必须全量重建。
- 伤害系统：`IDamageSystem.getDamageInfo(view)` 用 `view.getComputedEnemy()` 计算；`IDamageCalculator.calculate(handler)` 返回 `{ damage, turn }`；`getCriticalLimit` 提供临界计算上界；`DamageSystem.markDirty` / `markAllDirty` 维护缓存。
- 地图伤害按「计算后怪物」计算，因此光环新增的特殊属性会影响地图伤害；这一点在 `enemy-map-damage` 中级篇已提过，本篇只讲时序。
