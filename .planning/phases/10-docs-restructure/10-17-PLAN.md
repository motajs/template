**源码事实（写作时逐条核对）：**
- `Hookable`：`packages/common/src/hook.ts`。`addHook` 创建控制器、写入映射、把钩子加入列表、调用 `hook.awake`、再加入已加载列表并返回控制器；`removeHook` 按钩子对象查找并调用 `destroy`；`removeHookByController` 按控制器移除；`forEachHook` 只遍历已加载列表，文档注明「执行顺序不固定」。
- `addHook` 不去重：同一钩子实例再次注册会再创建一个控制器并再次加入列表，旧控制器仍留在映射里；结果是同一实例被多次调用。正文把它写成「行为事实 / 应当避免」，不要写成引擎缺陷。
- `awake` 在加入已加载列表之前调用；因此在 `awake` 内部由其他代码触发的事件不会回调到这个钩子。需要初始同步时，在 `awake` 里直接做。
- `IMapLayerHooks`：`packages-user/data-base/src/map/types.ts`；方法包括 `onResize`、`onUpdateArea`、`onUpdateBlock`、`onOpenDoor`、`onCloseDoor`、`onCreateDynamic`、`onDeleteDynamic`、`onUpdateDynamicPosition`。这些方法**不接收 layer 参数**。
- `IMapLayerHookController`：带 `layer` 与 `getMapData()`；控制器在 `MapLayer.createController` 里构造，能拿到所属图层。
- `IGameMapHooks`：`onChangeBackground(tile)`、`onUpdateLayer(layerList)`、`onResizeLayer(layer, width, height)`；`onResizeLayer` 回传具体图层。`GameMap.addLayer` 会给每个图层注册一个 `StateMapLayerHook`，把图层的 `onResize` 转发到地图级钩子并带上 layer。
- `IObjectMoverHooks`：`onMoveStart` / `onMoveEnd` / `onStepStart` / `onStepEnd` 接收 `tile` 与 `mover`；`onSetPos` / `onSetFaceDir` / `onSetMoveDir` 也接收 `tile`。移动器用 `Promise.all` 并发等待这些异步钩子。
- `IMapLayerHooks` 的 `onOpenDoor` / `onCloseDoor` / `onDeleteDynamic` 也返回 `Promise`，`MapLayer` 用 `Promise.all` 等待。
- `IHeroLocationHooks` 挂在 `state.hero.location`；`IHeroStateHooks` 挂在 `state.hero`；`IObjectMoverHooks` 挂在 `state.hero.location.mover`（见 `src/data/hook/initialize.ts`）。
- 异步钩子清单以源码为准；不要凭中级教程的清单补充未核对的方法。
