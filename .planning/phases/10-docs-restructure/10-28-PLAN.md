**源码事实（写作时逐条核对，勿凭印象）：**
- 三件套都在 `packages-user/data-common/src/common/mover.ts`：`IObjectMovable`（`x` / `y` / `setPos` / `getCurrentFaceDirection`）、`IObjectMover`（链式规划 + 状态 + `start`）、`IMoverController`（`done` / `onEnd` / `push` / `insert` / `stop`）。
- **命名更正：** D-75 写作 `IMoveController`，源码实际是 `IMoverController`。文档按源码写，并在 Task 0 向用户说明（D-13 / D-72）。
- 步骤联合类型 `ObjectMoveStep` 有 8 种：`Dir` / `DirFace` / `Speed` / `Face` / `Special` / `AnimDir` / `Teleport` / `Jump`；对应的 `type` 常量来自 `ObjectMoveType`；`ObjectSpecialStep` 有 `Forward` / `Backward`；`ObjectAnimDirection` 有 `Forward` / `Backward`。
- `step(dir, count)` 追加 `Dir`；`stepFace(move, face, count)` 追加 `DirFace`；`forward(count)` / `backward(count)` 追加 `Special`；`face(dir)` 追加 `Face`；`speed(value)` 追加 `Speed`（单位 ms/格，默认 `currentSpeed = 100`）；`animDir(dir)` 追加 `AnimDir`；`tp(x, y, rel)` 追加 `Teleport`；`jump(x, y, rel)` 追加 `Jump`；`push(steps)` 一次追加数组；`clear()` 清空尚未执行的队列。
- `start()`：已在移动时返回 `null`；否则把 `moveQueue` 切片成局部队列、调用 `clear()` 清空内部队列、`shouldStop = false`、`moveDirection` 重置为 `Unknown`，返回控制器并驱动执行。
- 执行顺序（`moveProgress`）：`onMoveStart`（子类）→ 钩子 `onMoveStart`（`Promise.all`）→ 每个步骤：`prepareStep`（先同步更新内部状态）→ `onStepStart`（返回 `code`）→ 钩子 `onStepStart` → `onStepEnd`（返回落点 `ITileLocator`）→ 坐标变化时 `tile.setPos` → `onStepSettled` → 钩子 `onStepEnd` → 全部步骤结束后 `onMoveEnd` → 钩子 `onMoveEnd`。
- 控制器：`push` / `insert` 只在仍在移动、未 `stop`、未 `done` 时生效；`insert` 把步骤放在「当前步之后」；`stop()` 把 `shouldStop` 置真并返回 `onEnd`，当前步会走完再停；`done` 在整次执行结束时置真，`onEnd` 同时兑现。
- **执行期间的坑：** `moveProgress` 用的是 `start()` 时的局部队列快照；执行期间再调用 `mover.step` / `mover.face` 等只会写回内部 `moveQueue`，不会被当前这一次执行消费。要在执行中追加，只能用 `controller.push` / `controller.insert`。
- `prepareStep` 的语义：`Dir` 同时写移动方向与朝向；`DirFace` 分开写；`Face` 只写朝向；`Special` 前进用当前朝向、后退用 `faceHandler.opposite(当前朝向)` 并保持朝向不变；`Speed` 写 `currentSpeed`；`AnimDir` 写 `currAnimDir`。
- `setPos` / `setFaceDir` / `setMoveDir` 立即生效、不排队，并分别触发 `onSetPos` / `onSetFaceDir` / `onSetMoveDir`；这三个钩子是同步的（返回 `void`）。
- 参考实现：`packages-user/data-base/src/hero/mover.ts`（`HeroMover` 继承 `ObjectMover`，实现边检、通行判断、撞击、步前步后事件，并在步进方法上标 `@shouldReplay`）、`packages-user/data-base/src/map/mover.ts`（`DynamicTileMover`，最小实现：只处理 8 种步骤的落点）。
- 现成入口：`state.hero.location.mover`（`IHeroMover`，另有 `config` / `getConfig` / `useTopImplementation`）、动态图块的 `mover` 字段；`IHeroMover` 与 `HeroMoveCode` 在 `packages-user/data-base/src/hero/types.ts`。移动器拿到的朝向处理器是 `IFaceHandler`（`packages/common/src/utils/types.ts`），本篇只说明「构造时要传一个」，细节由 10-29 的 `FaceHandler 系列` 承担。
- 通行性不在移动器里：`HeroMover` 把判断交给顶层实现对象（`IHeroMoveTopImpl` 的 `predicate` / `inBound`）。自定义移动器只负责「这一步落到哪」，通行判定属于调用方。
- 录像：`HeroMover` / `DynamicTileMover` 在会改状态的步进方法上标了 `@shouldReplay`；自定义移动器若要让移动进录像，同样标在改状态的方法上（详见 `./replay-consistency.md`）。
